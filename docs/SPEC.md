# Folio 명세

작성일: 2026-10-22. 원본 문서: https://claude.ai/artifact/Kdfm7BB9xt66Nv89KRz7jC

이 파일은 원본 문서를 내보낸 사본입니다. 명세를 고칠 때는 이 파일을 직접 고치고, 바뀐 결정은 커밋 메시지에 남깁니다.

## 개요

Folio는 과목을 중심에 두고 강의 자료, 노트, 손필기, 복습, 퀴즈, 과제, 성적을 하나로 묶는 macOS와 iPadOS용 네이티브 앱입니다. 노션, 아티팩트, 노타빌리티, Claude 프로젝트가 맡던 학업 관련 기능을 대체하고, 원본 파일은 iCloud의 GIST 폴더에 두되, Folio가 정한 표준 구조로 한 번 정리한 뒤 그 구조를 유지합니다. 옵시디언 볼트는 지금처럼 분야별 개념 노트 저장소로 남기며, Folio는 과목별 노트를 볼트와 별개로 직접 관리합니다. 기존 도구의 기능은 요구사항으로만 참고하고, UI는 처음부터 새로 설계합니다. 앱 이름은 Folio이며, 데이터 폴더(`.folio`), 명령줄 도구(`folio`), 번들 ID(`com.rhseung.folio`)도 같은 이름을 쓴다. 예전 이름은 Coursebook이었다.

### 목적

- 한 과목의 모든 정보를 과목 페이지 하나에서 확인하고 다룬다.
- 원본 파일을 한 곳에만 두고 중복 사본을 없앤다.
- 복습을 날짜가 아니라 단원 기준으로 관리해서 밀려도 우선순위가 보이게 한다.
- Claude를 과목 맥락이 자동으로 주어진 공부 도우미로 앱 안에서 쓴다.
- 학기 평점, 누적 평점, 전공 평점을 계산하고 목표 학점까지 필요한 점수를 역산한다.

### 성격

Folio는 노션처럼 사용자가 표와 속성을 직접 정의하는 범용 데이터베이스가 아닙니다. 학기, 과목, 단원, 강의, 평가 기준, 점수, 과제 같은 테이블이 처음부터 정해져 있고, 각 테이블은 목적에 맞는 전용 화면을 가집니다. 정해 두지 않은 정보는 과목과 학기마다 있는 자유 메모 칸에 적습니다.

### 제외 대상

- 학업과 무관한 할 일. 인포팀, 회사 업무 같은 일은 Todoist에서 계속 관리하며, Folio는 Todoist와 연동하지 않는다.
- 옵시디언 볼트의 관리. 볼트는 분야별 구조를 유지하고, Folio는 볼트의 파일을 읽거나 쓰지 않는다.
- 학교 LMS에서 과제와 공지를 자동으로 가져오는 기능. 보류 사항으로 남긴다.
- 기존 노타빌리티 필기의 변환. PDF로 내보내 참고 자료로만 보관한다.
- 범용 데이터베이스, 사용자 정의 속성, 공유와 협업 기능.

## 문제 대응

중간고사 기간에 격은 불편 사항과 각각을 해결하는 기능을 정리했습니다. 일부는 부분적으로만 해결되며, 해당 내용은 보류 사항 절에 적었습니다.

| 기존 문제 | 해결 방식 | 해결 수준 |
| --- | --- | --- |
| 학업 정보가 일곱 곳에 흩어져 있음 | 과목 페이지 하나에 강의록, 노트, 자료, 과제, 복습, 퀴즈, 성적을 모음. iCloud는 저장소로만 남음 | 해결 |
| 노션 데이터베이스로 전체 평점을 계산할 수 없음 | 전용 성적 테이블과 학점 규칙으로 학기, 누적, 전공 평점을 계산하고 목표 점수를 역산함 | 해결 |
| 평가 기준 일부를 애매하게 적음 | 비중과 반영 규칙을 구조화된 칸으로 입력함 | 해결 |
| 마크다운 표가 빈약하고 인터랙티브 요소를 넣을 수 없음 | 자체 렌더러에 표 블록, 위젯 블록, 정의와 정리 블록을 넣음 | 앱 안에서 해결 |
| 옵시디언 플러그인을 많이 설치해도 한계가 남음 | 필요한 문법을 렌더러에 직접 구현함 | 해결 |
| 진도, 퀴즈, 공부 계획을 둘 곳이 없어 아티팩트를 따로 만듦 | 단원 단위의 진도, 퀴즈 탭, 계획 타임라인을 앱에 넣음 | 해결 |
| Todoist 복습 반복 일정이 계속 밀림 | 단원 기준 간격 반복 스케줄러와 밀린 항목의 우선순위 정렬 | 해결 |
| 자정이 지나면 할 일이 다음 날로 넘어감 | 하루 경계 시각을 설정함 | 해결 |
| 노타빌리티 필기를 채점받으려면 PDF 변환이나 캐처가 필요함 | iPad에서 PencilKit으로 앱 안에 필기하고 Claude가 바로 채점함 | 해결. 단, 필기는 iPad에서만 가능 |
| Claude 데스크톱 앱의 창이 하나뿐이고 너무 큼 | 과목 페이지마다 크기를 조절할 수 있는 Claude 패널과 과목별 대화 | 해결 |
| Claude 프로젝트에 족보와 렉처를 따로 올려야 함 | 과목 폴더를 맥락으로 삼아 자동으로 넘김 | 해결 |
| 같은 파일이 iCloud, 노타빌리티, 프로젝트에 중복됨 | 원본은 과목 폴더에만 두고, 필기는 별도 파일, Claude에는 위치만 넘김 | 해결 |
| Finder에서 파일을 마음대로 옮기면 구조가 깨짐 | 파일을 고유 식별자로 추적하고 미분류 파일을 인박스로 흡수함 | 해결 |
| 과제 공지와 마감을 직접 입력해야 함 | 한 줄 빠른 추가와 과제 PDF 자동 인식 | 부분 해결. LMS 연동은 보류 |

## 기술 기반

SwiftUI 멀티플랫폼 프로젝트 하나로 macOS 26과 iPadOS 26을 동시에 지원합니다. 최소 지원 버전을 26으로 두는 이유는 Liquid Glass 디자인을 시스템 기본 구성 요소로 쓰기 위해서입니다.

### 플랫폼별 역할

| 플랫폼 | 주요 용도 | 제약 |
| --- | --- | --- |
| macOS 26 | 노트 작성, 성적과 과제 관리, 퀴즈, Claude 대화, 자료 정리 | 펜 입력이 없어 필기는 읽기만 가능 |
| iPadOS 26 | 손필기, 렉처와 필기 나란히 보기, 손글씨 풀이 채점, 복습 | 키보드 없이 긴 노트를 쓰기 불편함 |

### 구성 요소

- **UI**: SwiftUI. 사이드바는 `NavigationSplitView`로 구성해서 시스템의 떠 있는 유리 재질을 그대로 쓴다. 직접 만든 툴바와 플로팅 패널에는 `.glassEffect()`를 적용한다.
- **파일 접근**: iCloud Drive의 GIST 폴더를 사용자가 한 번 지정하고, security-scoped bookmark로 접근 권한을 유지한다. 변경 감지는 `NSMetadataQuery`와 `NSFilePresenter`를 쓴다.
- **인덱스 캐시**: 기기별 로컬 SQLite. 검색, 전체 평점, 오늘 화면 집계를 빠르게 하기 위한 것이며, 삭제되어도 과목 폴더에서 다시 만들 수 있다.
- **필기**: PencilKit. 획 데이터는 `PKDrawing`으로 저장한다.
- **PDF 표시**: PDFKit.
- **노트 렌더링**: 마크다운 파서는 swift-markdown을 기반으로 확장 문법을 추가한다. 수식은 KaTeX로 그린다. 읽기 화면은 페이지 스크립트를 끈 채 앱 전용 스크립트 영역에서 수식만 조판한다.
- **노트 편집기**: CodeMirror 6(옵시디언과 같은 편집기)를 웹 뷰에 넣고 실시간 미리보기를 직접 구현한다. KaTeX, AsciiMath 변환기(asciimath2tex), CodeMirror는 `web/`에서 npm으로 받아 번들로 묶는다.
- **위젯**: `WKWebView`. 앱과의 데이터 교환은 메시지 핸들러로 한다.
- **내보내기**: Typst. Rust 라이브러리를 앱에 포함해 PDF를 만든다.
- **Claude**: Claude Code CLI를 하위 프로세스로 호출하는 방식과 Claude API를 직접 호출하는 방식을 모두 지원하도록 연동 계층을 추상화한다. 자세한 내용은 Claude 연동 절에 적는다.
- **명령줄 도구**: `folio`. 앱과 같은 액션 구현을 써서 모든 데이터 조작을 터미널과 에이전트에 연다. 명령줄 도구 절 참조.

### 디자인 기준

참고 앱은 [The Markdown Editor](https://themarkdowneditor.app/)입니다. 투명한 사이드바, 문서 중심의 넓은 본문, 필요할 때만 나타나는 도구 막대를 기본으로 합니다. 과목마다 고유한 강조색을 두고, 과목 페이지에서는 그 색을 강조 요소에만 씁니다. 노션 과목 페이지와 중간고사 대비 아티팩트의 화면 구성은 따르지 않고, 필요한 기능만 가져와 새로 배치합니다. 라이트 모드와 다크 모드를 모두 지원합니다.

## 저장 구조

Folio의 모든 데이터는 iCloud Drive의 기존 GIST 폴더(`Me/GIST`) 안에 파일로 저장합니다. 폴더 구조와 파일 이름은 Folio가 정한 표준을 따르며, 기존 폴더는 이 표준에 맞춰 한 번 정리합니다. 앱 내부 데이터베이스는 캐시일 뿐이므로, 폴더만 있으면 어느 기기에서나 모든 상태를 복원할 수 있습니다.

### 표준 폴더 구조

Folio가 GIST 폴더의 구조를 정하고, 모든 학기와 과목에 같은 구조를 적용합니다. 기존 iCloud 폴더는 이 구조에 맞춰 한 번 정리하고(아래 기존 폴더 정리 참조), 그 뒤에는 앱이 구조를 유지합니다.

과목 폴더는 다음 세 묶음으로 나뉩니다.

- **받은 자료**: 교수와 학교가 준 것. `Syllabus`, `Lectures`, `Exercises`, `Textbooks`
- **해야 할 일**: 마감이나 일정에 묶인 것. `Assignments`, `Exams`
- **내가 만든 것**: `Notes`, `Ink`, `Recordings`, `Archive`

```text
Me/GIST/
  .folio/
    transcript.json            # 학기별 이수 기록, 인정학기, 학점 규칙, 목표
    catalog.json               # 강의 코드, 세부 분류, 평어, 교수 정보
    settings.json              # 하루 경계, 복습 간격, 사이드바 과목 순서 등 전역 설정
  2026-3/
    _Admin/                    # 학기 전체의 시험 시간표, 강의실 배정, 수강신청 서류, 성적증명서
    EC4207 그래프 이론/
      Syllabus/                # 강의계획서, OT 자료, 수업 운영 안내
      Lectures/                # 강의 슬라이드. 05_Matchings.pdf
      Exercises/               # 교수가 준 채점 없는 연습 문제
      Textbooks/               # 교재, 참고서, 해설집
      Assignments/
        HW03/                  # 과제 하나에 폴더 하나
          26h3.pdf             # 문제. 원래 이름 유지
          HW3-5070류현승.pdf  # 제출본. 원래 이름 유지
        Lab03/                 # 실험 보고서. 매뉴얼은 그 실험 회차의 강의 자료로 Lectures에 둠
      Exams/
        Past/                  # 족보. 2024 Midterm (소순범).pdf
        Midterm/               # 이 시험 하나에 딸린 파일
          Guideline.pdf        # 시험 안내
          Seating.pdf          # 자리 배치표
          Problems.tex, Problems.pdf, Proofs.tex, Proofs.pdf, Solutions.pdf
          Summary.pdf          # 시험 종합 정리 노트를 내보낸 것
        Final/
      Notes/                   # Folio 마크다운 노트
        assets/                # 노트에 넣은 그림과 파일. 같은 이름이면 번호를 붙임
      Ink/                     # PencilKit 필기 (.drawing)
      Recordings/              # 강의 녹음(.m4a)과 받아쓰기(.transcript.json). 2주차-1.m4a
      Archive/                 # 이전 필기 (노타빌리티 PDF, 예전 노트 폴더)
      .folio/
        course.json            # 과목 정보, 단원, 강의 회차, 평가 기준, 과제, 파일 연결
        quizzes/<단원 ID>.json
        chats/<대화 ID>.json
        widgets/<위젯 ID>.html
        moves.jsonl            # 앱이 수행한 이동과 이름 변경 기록
        logs/<기기 ID>.jsonl  # 복습, 퀴즈, 공부 시간 기록 (기기별 추가 전용)
```

### 이름 규칙

- 학기 폴더는 `<연도>-<번호>`다. 번호 1은 봄학기, 2는 여름학기, 3은 가을학기, 4는 겨울학기다.
- 학기 폴더 안에는 `_Admin`과 과목 폴더만 둔다. 학기 폴더에 파일을 직접 두지 않는다.
- 과목 폴더는 `<대표 과목코드> <과목명>`이다. 예를 들어 `EC4207 그래프 이론`이다. 과목명, 코드, 일련번호의 원본은 `course.json`이고 폴더 이름은 그 값을 따른다. 과목 편집에서 이 값을 바꾸고 저장하면 앱이 폴더 이름을 맞춰 바꾸며, 저장 전 화면에 새 이름을 보여 주는 것이 승인이다. 이름 변경은 `moves.jsonl`에 기록한다.
- 과목 폴더의 하위 폴더는 위 목록만 쓴다. 앱은 과목을 만들 때 `Syllabus`, `Lectures`, `Assignments`, `Exams`, `Notes`를 만들고, 나머지는 처음 필요할 때 만든다. 과목 폴더 최상위에는 파일을 두지 않는다.
- `Lectures`의 파일은 `<주차 두 자리>_<제목>`으로 이름을 붙인다. 한 주에 여러 파일이면 `05-1_`, `05-2_`처럼 나눈다. 주차가 파일 이름에 있어야 Finder에서도 순서대로 보인다.
- `Assignments`는 과제마다 폴더를 하나 둔다. 폴더 이름은 종류 접두어와 두 자리 번호다.
  - 접두어는 `HW`(숙제), `Lab`(실험), `Report`(보고서), `Project`(프로젝트), `SP`(Slow Problem), `Reading`(읽기 과제)를 기본으로 하고, 과목의 평가 항목에 맞춰 추가할 수 있다.
  - 폴더 안의 파일은 원래 이름을 그대로 둔다. 제출본은 교수가 정한 형식(예: 학번과 이름 포함)을 따라야 하므로 앱이 이름을 바꾸지 않는다. 문제, 제출본, 해설, 매뉴얼 같은 역할은 앱이 `course.json`에 기록한다.
  - 코드 과제는 프로젝트를 이 폴더 안에 그대로 둔다.
  - 실험 매뉴얼은 그 실험 회차에서 쓰는 자료이므로 `Lectures/<주차>_<이름>`에 두고 그 실험의 단원에 연결한다. 실험 보고서는 과제로 보고 그 실험의 단원에 연결하며 `Lab<번호>`나 `Report<번호>` 폴더에 둔다.
- `Exams`는 두 종류의 폴더를 둔다.
  - `Past`: 족보. 여러 해의 자료라 특정 시험에 묶지 않는다. 파일 이름은 `<연도> <Midterm|Final|Quiz> (<출처>)`다. 출처는 담당 교수나 자료를 준 사람이며 없으면 생략한다. 해설은 같은 이름에 `  Solution `을 붙인다.
  - 시험별 폴더: `Midterm`, `Final`, 퀴즈가 여러 번이면 `Quiz1`, `Quiz2`. 데이터 모델의 Exam과 1:1로 대응한다. 시험 안내(`Guideline`), 자리 배치표(`Seating`), 직접 만든 문제집과 해설, 종합 정리 PDF(`Summary`)를 둔다. 대비 자료가 없는 작은 퀴즈는 폴더를 만들지 않는다.
- `Exercises`에는 교수가 준 연습 문제만 둔다. 직접 만든 문제집은 대상 시험 폴더에 둔다.
- 노트를 내보낸 PDF는 용도에 맞는 곳에 저장한다. 시험 종합 정리는 해당 시험 폴더에, 그 밖의 노트는 `Notes/Exports`에 둔다.
- GIST 폴더 최상위에는 학기 폴더와 `.folio`만 둔다.

### 구조 유지

- 앱이 만들거나 가져오는 파일은 처음부터 표준 위치에 저장한다. 예를 들어 과제를 등록하면 `Assignments/HW03/`을 만들고, 시험을 등록하면 `Exams/Midterm/`을 만든다.
- 앱 밖의 파일은 복사해서 들여온다. 원본은 그대로 두고, 같은 이름이 있으면 ` 2`를 붙여 덮어쓰지 않는다. 들여온 파일은 바로 추적 목록에 넣는다.
    - 과제 행과 과제 편집 화면, 시험 카드에 끌어다 놓으면 그 과제나 시험 폴더로 복사한다. 과제 편집 화면에는 "파일 추가" 버튼도 둔다. 과제 파일의 문제와 제출본 구분은 파일 이름으로 추정한다.
    - 회차 행에 끌어다 놓으면 `Lectures/<주차>_<이름>`으로 복사하고 그 회차에 연결한다. 이미 과목 안에 있는 파일이면 복사하지 않고 연결만 한다.
    - 자료 화면에서는 "파일 추가"로 고르거나 화면에 끌어다 놓은 뒤 넣을 곳을 고른다. 강의 자료, 강의계획서, 연습 문제, 교재, 이전 필기, 족보, 각 과제 폴더, 각 시험 폴더가 있다. 강의 자료는 회차를 고르면 주차 이름을 붙이고 그 회차에 연결한다.
- 자료 화면에서 파일 이름을 바꾸거나 다른 표준 폴더로 옮기고, 휴지통으로 보낼 수 있다. 이름 바꾸기와 옮기기는 `moves.jsonl`에 남겨 "방금 옮긴 것 되돌리기"로 되돌리고, 휴지통으로 보내기는 확인을 받은 뒤 실행한다. 자료 ID와 회차, 단원 연결은 유지한다.
- 자료 화면은 역할마다 파일을 폴더 트리로 보여 준다. 모든 파일이 공유하는 폴더(`Assignments`)는 블록 제목 옆에 적고, 그 아래 폴더(`HW03`)는 파일 수와 함께 접힌 채로 두어 눌러서 편다. 파일은 이름만 보인다.
- 자료 행과 과제 파일 행은 앱 밖으로 끌어낼 수 있다. 과제를 LMS에 올릴 때 Finder를 거치지 않는다.
- Finder에서 표준 위치가 아닌 곳에 파일을 넣으면 미분류 목록에 띄운다. Claude가 표준 위치와 이름을 제안하고, 사용자가 승인하면 앱이 옮긴다.
- 표준 목록에 없는 하위 폴더가 생기면 경고를 띄우고, 어느 표준 폴더로 합칠지 제안한다.
- 사용자가 승인하지 않은 이동, 이름 변경, 삭제는 하지 않는다. 앱이 수행한 모든 이동과 이름 변경은 `.folio/moves.jsonl`에 기록해 되돌릴 수 있게 한다.
- 노트는 표준 마크다운이고 파일 이름은 앱이 제목으로 붙인다. 앱은 노트를 frontmatter의 `id`로 식별하므로 제목을 바꿔도 연결이 유지된다.
- 옵시디언 볼트와는 파일을 공유하지 않는다. 볼트의 개념 노트는 `obsidian://open` 링크로만 참조한다.

### 기존 폴더 정리

2026년 10월 22일에 확인한 iCloud GIST 폴더는 학기마다 하위 폴더 이름이 다릅니다. 2026 봄학기까지는 한국어 이름을, 2026 가을학기부터는 과목마다 다른 영어 이름을 썼습니다. 이것을 한 번 표준 구조로 옮깁니다.

| 기존 위치 | 옮길 위치 |
| --- | --- |
| `강의자료`, `Lectures` | `Lectures`. 파일 이름에 주차를 붙인다 |
| `숙제`, `Homeworks`, `Assignments`, `Slow Problems`, `Reports` | `Assignments/<과제>`. 문제, 제출본, 해설을 과제별로 묶고 파일 이름은 유지한다 |
| `Manuals`(실험 매뉴얼) | `Lectures/<주차>_<이름>`. 주차는 그 실험 단원에 연결된 첫 회차에서 가져오고, 모르면 확인 대상으로 표시한다 |
| `족보`, `족보 (소순범)` | `Exams/Past`. 출처는 파일 이름에 넣는다 |
| `Exam Review` | 대상 시험 폴더. 이번 학기 자료는 `Exams/Midterm` |
| 과목 폴더 최상위의 시험 안내, 자리 배치표 | 대상 시험 폴더 |
| `Exercises` | `Exercises` |
| `Books`, 과목 폴더 최상위의 교재 PDF | `Textbooks` |
| 과목 폴더 최상위의 강의계획서, OT 자료, 실험 스케줄, 수학 클리닉 시간표 | `Syllabus` |
| `노트` | 마크다운은 `Notes`로 가져오고, 나머지는 `Archive` |
| 학기 폴더의 `학사`와 학기 폴더에 직접 놓인 학사 파일 | `_Admin` |
| `대회`(탁구로봇) 처럼 과목 고유의 폴더 | 개별 확인. 기본은 `Assignments/Project01` |

- 정리는 파일 내용을 바꾸지 않고 이동과 이름 변경만 한다.
- 먼저 전체 이동 계획을 표로 만들어 보여 주고, 사용자가 승인한 뒤 실행한다. 파일을 어느 과제나 시험에 묶을지 같은 판단은 Claude가 제안하고, 확신이 낮은 항목은 따로 표시한다.
- 실행 전에 GIST 폴더 전체를 iCloud 밖에 백업하고, 실행 기록을 `.folio/moves.jsonl`에 남겨 한 번에 되돌릴 수 있게 한다.
- 과제 폴더 안의 코드 프로젝트는 폴더 단위로 옮기고 내부는 건드리지 않는다. `.git`이 있는 폴더는 이름도 바꾸지 않는다.
- GIST 폴더에 있는 학업 외 폴더(`과대표`, `기숙사`, `기타`, `GIST OTP`, `무한도전 프로젝트`)와 `2026-2`에 놓인 경진대회 자료는 사용자가 옮길 위치를 정한다. 보류 사항 절 참조.

### 색인 제외 대상

- `.git`, `node_modules`, `__pycache__`, `.venv`, `build`, `dist`를 포함하는 폴더는 코드 프로젝트로 보고 내부를 색인하지 않는다. 자료 목록에는 폴더 하나로 표시하고, 누르면 Finder에서 연다.
- 하위 파일이 500개를 넘는 폴더도 같은 방식으로 처리하고, 사용자에게 색인 여부를 묻는다.
- `.DS_Store`, `~$`로 시작하는 Office 임시 파일, `.pyc` 같은 빌드 산출물은 무시한다.
- `.tex` 파일은 같은 이름의 PDF가 있으면 그 PDF의 원본으로 묶어서 하나의 자료로 보여 준다.

### 파일 추적

- 파일을 경로로 기억하지 않고, 처음 등록할 때 고유 ID를 부여해 `course.json`에 기록한다.
- 파일 항목은 ID, 마지막으로 확인한 상대 경로, 파일 크기, 내용 해시(SHA-256), bookmark data를 가진다.
- 파일을 열 때는 bookmark를 먼저 해석한다. bookmark가 깨졌으면 과목 폴더 안에서 내용 해시가 같은 파일을 찾고, 찾으면 경로와 bookmark를 갱신한다.
- 둘 다 실패하면 해당 항목을 "파일 없음" 상태로 표시하고, 사용자가 다른 파일을 지정하거나 연결을 끊을 수 있게 한다. 연결된 단원, 퀴즈, 노트의 참조는 자동으로 지우지 않는다.
- 노트 안의 내부 링크도 경로가 아니라 ID로 저장해서 파일 이동의 영향을 받지 않게 한다.
- 과목 폴더를 다른 학기 폴더로 옮기거나 이름을 바꿔도 `course.json`이 함께 옮겨지므로 같은 과목으로 인식한다.

### 미분류 파일

- `course.json`에 없는 파일이 과목 폴더에 생기면 해당 과목의 미분류 목록에 띄운다. 폴더 역할이 정해진 하위 폴더에 들어온 파일은 종류를 묻지 않고 그 역할로 분류한다.
- Claude가 파일 내용을 읽고 종류, 연결할 단원이나 강의 회차를 제안한다. 예를 들어 `26_week5.pdf`는 5주차 강의 자료로, `26h3.pdf`는 과제 3의 문제로, `HW3-5070류현승.pdf`는 과제 3의 제출본으로 제안한다.
- 과제 문서로 판단되면 제목과 마감일을 추출해 과제 등록까지 함께 제안한다.
- Claude가 표준 위치와 파일 이름을 함께 제안하고, 사용자가 승인하면 옮긴다. 승인 없이 파일을 옮기거나 이름을 바꾸지 않는다.

### 동기화와 충돌 방지

- 동기화는 iCloud Drive에 맡긴다. 별도 서버는 두지 않는다.
- 자주 바뀌는 기록(복습 결과, 퀴즈 풀이, 공부 시간)은 기기별 로그 파일에 추가만 한다. 각 기기는 자기 로그 파일에만 쓰므로 두 기기가 같은 파일을 동시에 수정하는 일이 없다. 읽을 때는 모든 기기의 로그를 시각순으로 합쳐 상태를 계산한다.
- 드물게 바뀌는 구조 데이터(단원, 평가 기준, 과제)는 `course.json`에 저장한다. 각 항목은 수정 시각과 기기 ID를 가진다.
- iCloud가 충돌 사본을 만들면 `NSFileVersion`으로 감지하고, 항목 단위로 수정 시각이 더 늦은 쪽을 채택해 병합한다. 같은 항목이 양쪽에서 바뀌었으면 사용자에게 어느 쪽을 남길지 묻는다.
- 노트와 필기 파일은 파일 단위로 충돌을 처리한다. 충돌 사본이 생기면 두 버전을 나란히 보여 주고 사용자가 선택한다.
- 아직 내려받지 않은 iCloud 파일은 목록에 표시하되, 열 때 내려받는다. Claude에 맥락으로 넘길 파일은 미리 내려받는다.

### 백업

- iCloud 동기화는 백업이 아니므로 별도의 백업을 둔다. 한 기기에서 지운 파일은 모든 기기에서 지워지기 때문이다.
- Mac 앱은 하루에 한 번 GIST 최상위의 `.folio`과 각 과목의 `Notes, Ink`, `.folio`을 iCloud 밖의 로컬 폴더에 날짜별 압축 파일로 복사한다. 강의 자료와 과제 같은 원본 자료는 다시 구할 수 있으므로 기본값에서는 제외한다.
- 보관 기간은 최근 30일은 매일, 그 이전은 주 1회로 둔다.
- 선택 기능으로, 사용자가 지정한 비공개 git 저장소에 노트와 메타데이터를 커밋하고 push할 수 있게 한다.
- 앱 안에서 백업 시점을 골라 과목 단위로 복원할 수 있게 한다.

## 화면 구성

이 절은 어떤 화면이 있고 각 화면이 무엇을 보여 주고 무엇을 할 수 있는지만 정합니다. 배치, 시각 위계, 상호작용 방식은 별도의 디자인 작업에서 새로 정합니다.

### 창과 탐색

- 사이드바에는 오늘, 현재 학기의 과목 목록, 성적, 졸업 요건, 교수와 조교, 강의 코드, 전체 미분류, 지난 학기가 있다.
- 사이드바의 학기 안 과목은 끌어서 순서를 바꾼다. 순서는 `settings.json`의 `sidebar.courses`(과목 ID 목록)에 남아 기기 사이에 함께 맞춰지고, 목록에 없는 과목(새 과목)은 이름순 자리에 들어간다. 학기는 날짜순으로 두고 옮기지 않는다. 사이드바 순서는 과목의 기본 강조색을 고르는 학기 안 순서(이름순)를 바꾸지 않는다.
- 졸업 요건 페이지는 졸업 학점(최상위 분류의 최대 인정 학점을 넘는 몫은 빼고 센다), 평점 하한, 세부 분류 트리의 학점과 과목 수 진행, 분류 없는 과목을 보여 주고 세부 분류를 편집한다. 요건 값은 학사편람에서 옮겨 적고, 출처를 분류의 `rule`에 남긴다. 편람의 요건 표는 `folio import-requirements`로 한 번에 넣을 수 있다. 내 정보(설정의 탭이며 이 페이지에서도 연다)에서 입학 연도와 선언한 과정(주전공, 복수전공, 부전공, 심화전공)을 고르고, `programId`가 선언하지 않은 과정을 가리키는 분류는 요건 계산과 분류 선택에서 빠진다. 인문사회의 HUS, PPE처럼 편람 표로만 가릴 수 있는 분류는 `catalog.json`의 `handbooks`(연도별 과목 코드 → 분류 이름 표, `folio import-handbook`으로 넣는다)로 제안하고, 과목을 들은 해의 편람만 본다. 제안은 졸업 요건 페이지에서 승인해야 적용된다. 졸업 요건 페이지의 알림(편람과 다른 분류, 이중 계산 상한 초과, 함께 셀 수 없는 과목, 분류 없는 과목)은 FolioDomain의 `RequirementAudit` 한 곳에서 판정하고, `folio requirement check`가 같은 결과를 보여 준다(정할 것이 있으면 종료 코드 4). 판정마다 이름(`handbook`, `shared`, `unallowed`, `unassigned`)이 있어 `--only`로 골라 볼 수 있고, 판정을 더할 때는 이름과 결과를 함께 더하며 과목 데이터베이스처럼 새로 읽을 자료는 판정의 입력으로 받는다. `folio requirement check <과목>`은 한 과목의 분류, 들은 해 편람의 분류, 이중 계산 여부를, 아직 듣지 않은 강의 코드는 편람 분류 표에서 찾은 분류를 보여 준다. 새 편람의 분류 표는 1년에 한 번 에이전트가 편람에서 옮겨 `import handbook --dry-run`으로 보여 주고 사용자가 승인해 넣는다. 그 절차는 folio 스킬에 적는다.
- 복수전공은 주전공과 최대 9학점까지 이중 계산하고 부전공은 이중 계산하지 않는다(학사편람). 과목을 두 과정의 분류에 함께 넣는 것이 그 과목을 이중 계산에 쓰겠다는 선택이며, 앱이 대신 고르지 않는다. 함께 넣은 학점이 분류의 `maxSharedCredits`를 넘으면 넘는 몫을 그 분류(와 상위 분류)의 학점에서 빼고, 졸업 요건 페이지에 겹친 과목과 분류 선택을 보여 준다. 공통 분류와 겹치는 것은 이중 계산이 아니다. 함께 셀 수 있는 과목은 두 과정의 코드를 모두 가진 강의 공유 과목과 `sharingApproved`인 학과별 인정 과목뿐이다(코드는 접두어로 맞춘다). 분류 메뉴는 그 밖의 과목을 두 과정에 함께 넣지 못하게 막고, 이미 함께 들어 있으면 상한이 있는 분류에서 그 학점을 모두 빼고 졸업 요건 페이지에서 분류 선택과 학과 인정 표시를 보여 준다.
- 교수와 조교 페이지는 사람 목록과 연락처, 연구실, 면담 시간, 메모를 편집하고, 맡은 과목을 Course의 instructorIds로 역산해 보여 준다. 이메일을 누르면 기본 메일 앱에서 메일 초안을 연다(`mailto:`). 강의 코드 페이지는 접두어와 학과로 코드를 찾고 표를 편집한다.
- macOS에서는 과목마다 별도 창을 열 수 있다. 한 창 안에서는 탭으로 여러 화면을 열어 둔다.
- iPadOS에서는 Split View와 Stage Manager를 지원하고, 앱 안에서도 화면을 좌우로 나눠 두 화면을 동시에 띄울 수 있다. 예를 들어 왼쪽에 렉처, 오른쪽에 필기를 둔다.
- 전역 검색으로 모든 과목의 노트, 자료 제목과 PDF 본문, 퀴즈, 과제를 찾는다. 명령 팔레트로 화면 이동과 빠른 추가를 실행한다.
- Claude 패널은 어느 화면에서나 열고 닫을 수 있는 보조 영역이다. 크기를 조절할 수 있고, 떼어내서 별도 창으로 띄울 수도 있다.

### 오늘 화면

모든 과목에서 오늘 해야 할 일을 모아 보여 주는 시작 화면입니다. 오늘의 범위는 설정한 하루 경계를 따릅니다.

- 다가오는 시험의 D-day
- 오늘 복습: 아직 복습 노트를 쓰지 않은 지난 강의 회차를 먼저, 그 아래 오늘 복습할 단원과 밀린 단원을 우선순위 순으로 한 목록에 둔다. 오늘 수업도 끝나는 시각부터 회차가 들어간다(복습 노트는 그날 쓴다). 회차를 누르면 그 회차의 복습 노트를 만들어 연다. 노트를 만들기만 해서는 끝나지 않고, "작성 완료"로 표시해야 목록에서 빠진다
- 남은 과제 마감 전부. 가까운 순이며 기간으로 자르지 않는다
- 오늘 수업이 있는 과목
- 시험 계획이 있으면 그날의 계획 항목
- 최근 2주의 과목별 공부 시간
- 빠른 추가 입력란. 과제, 시험, 메모를 한 줄로 추가한다

### 과목 화면

과목의 모든 정보가 모이는 화면입니다. 상단 요약과 여러 하위 화면으로 구성합니다.

- **상단 요약**: 강의 코드, 일련번호, 학점, 교수, 평가 방식, 다음 수업, 다음 시험까지 남은 날, 오늘 복습할 단원 수, 가장 가까운 과제 마감, 현재 환산 점수
- **강의**: 강의 회차 목록. 주차로 묶고, 달이 바뀌는 곳에 달을 표시한다. 회차마다 이름과 주제, 다룬 단원(하위 단원이 있으면 가장 깊은 것만), 러프 노트, 복습 노트, 필기, 렉처 파일, 출결을 보여 주고 바로 연다. 러프와 복습 노트는 위아래로 맞춘 고정 칸에 두고, 없는 복습 노트는 그 칸에서 바로 만든다. 단원은 행에서 바로 연결하고, 수업했는데 단원이 없는 회차는 "단원 연결 필요"로 표시한다. 수업 시간표로 다음 강의를 제안한다
- **단원**: 단원 목록과 단원별 진도, 복습 상태, 퀴즈 정답률, 남은 오답 수. 하위 단원이 있는 최상위 단원(장)은 제목 아래 하위 단원을 묶고, 단원마다 연결된 회차를 보여 준다. 시험 범위는 장과 다를 때만 하위 단원에 표시한다. 단원이 없는 지난 회차는 목록 위에 모아 그 자리에서 연결한다. 단원을 열면 관련 회차, 노트, 자료, 퀴즈, 위젯이 모여 있다
- **노트**: 이 과목의 모든 노트. 종류별(러프, 복습, 시험 종합 정리, 단원 정리, 자유)로 걸러 본다
- **자료**: 폴더 역할별로 묶은 파일 목록과 미분류 목록. PDF는 앱 안에서 열고, 다른 형식은 기본 앱으로 연다
- **과제**: 마감 순 목록. 상태, 문제 파일, 제출본, 점수를 보여 준다
- **성적**: 평가 항목, 하위 점수, 규칙, 환산 점수, 목표 등급까지 필요한 점수, 출결 현황과 결석 상한까지 남은 횟수
- **퀴즈**: 범위와 유형을 골라 퀴즈를 푼다. 문제 묶음의 문제별 기록도 여기서 본다. 풀기, 카드, 오답과 통계, 문제 묶음은 화면 안의 탭이 아니라 과목 열에서 퀴즈 아래 하위 항목으로 고른다
- **시험**: 시험별 범위, 일시, 장소, 시험 종합 정리 노트, 시험 계획 타임라인
- **정보**: 교수와 조교 연락처, 강의계획서, 수업 시간과 강의실, 자유 메모

## 강의와 성적, 과제

### 강의 회차

- 회차는 수업이 있을 때 만든다. 학기 전체를 미리 만들지 않는다. 수업 시간표로 지금 진행 중이거나 다음에 올 강의 하나를 점선 카드로 제안하고(회차 화면, 오늘 화면, 지금 수업 카드), 사용자가 "만들기"를 누르거나 그 카드에서 러프 노트나 녹음을 시작하면 회차가 만들어진다. 이미 그 시각에 회차가 있으면 다음 강의를 제안한다. 수업 시간은 과목 편집에서 바꾸고, 회차 화면에서는 제안 카드의 ⋯ 메뉴에서도 바꾼다. 수업 시간이 비어 있으면 회차 화면 위에 수업 시간을 넣으라는 카드를 둔다.
- 시험 주(학기의 중간고사 주와 기말고사 주, 봄·가을학기 기본 8주차와 16주차)에는 회차를 제안하지 않는다. 그 밖의 주에도 과목의 퀴즈가 아닌 시험이 수업 시간과 겹치면 그 수업은 제안하지 않는다. 시험 주는 학기 화면의 기간 카드에서 바꾼다.
- 회차에는 종류가 없다. 리시테이션, 보강처럼 시간표에 없는 수업도 "회차 추가"에서 날짜와 시간을 넣어 만드는 같은 회차다. 실험은 단원으로 다룬다. 실험 하나가 `Lab<번호> <실험 이름>` 단원 하나이고, 실험 회차, 실험 보고서 과제, 매뉴얼 자료가 그 단원에 연결된다. 실험 번호는 단원의 제목과 순서에 있다.
- 주차는 학기 시작일이 있는 주를 1주차로 하는 월요일 기준 주로 센다. 새 회차는 그 주의 마지막 순서가 된다.
- 예전에 미리 만들어 둔 앞으로의 회차 중 노트, 녹음, 출석, 자료, 단원이 하나도 연결되지 않은 것은 회차 화면에서 보여 주고, 사용자가 승인하면 지운다.
- 시험 날처럼 수업이 없던 날 잘못 만든 회차는 회차 메뉴의 "회차 삭제"로 확인을 받고 지운다. 노트, 녹음, 출석, 자료, 단원이 연결된 회차는 지우지 않고 휴강으로 표시하도록 안내한다. 지워도 같은 주의 다른 회차 이름은 바뀌지 않는다.
- 회차 화면은 회차를 주차별 타임라인으로 보여 준다. 왼쪽에 날짜와 요일(달은 바뀌는 곳에만), 가운데에 레일, 오른쪽에 제목과 시간, 끝에 노트를 둔다. 제목은 주제, 없으면 연결된 단원, 그것도 없으면 회차 이름이고, 회차 이름은 툴팁으로 본다. 결석, 공결, 지각은 제목 옆에 붙이고 출석은 표시하지 않는다. 제목 아래에는 시간과, 제목과 다른 단원만 작게 둔다. 단원이 제목과 같으면 연결 아이콘만 남긴다. 주차 줄은 구분만 하므로 회차 제목보다 작고 옅게 쓴다. 레일과 점은 지난 회차까지 과목 색이고 앞으로는 회색이며, 앞으로의 회차는 흐리게 그리고 `내일 오후 1:00`, `3일 후`처럼 남은 날을 적는다. 지금 진행 중인 회차는 레일의 점이 수업이 지난 만큼 차오르는 고리가 되고, 남은 분을 적는다. 중간고사와 기말고사는 레일 위에 표시하고, 이번 주의 주차에는 `이번 주`를 붙인다.
- 회차 이름은 `2주차-1`처럼 주차와 그 주의 순서로 붙인다. 리시테이션도 순서에 넣어 `2주차-3`처럼 부른다.
- 공휴일과 휴강은 제안 카드에서 "휴강"으로 `cancelled` 회차를 남기거나 회차 메뉴의 "휴강"으로 있는 회차에 표시한다. 보강은 회차를 하나 더 추가한다.
- 수업이 시작되면 오늘 화면과 과목 화면에서 그 회차의 러프 노트를 한 번에 열 수 있다. 러프 노트는 처음 열 때 만들어진다.
- 진도 없이 채점만 한 날처럼 복습할 것이 없는 회차는 "복습 필요 없음"으로 표시한다. 그 회차는 복습 노트를 요구하지 않고, 연결된 단원의 복습 주기도 다시 시작하지 않는다. 과목 전체를 복습에서 빼는 설정과는 별개다.
- 러프 노트가 있는 회차에서는 "복습 노트 만들기"를 제공한다. 러프 노트, 필기, 그 회차의 렉처를 Claude에 넘겨 복습 노트 초안을 만들거나, 빈 복습 노트를 만들어 직접 쓸 수 있다.
- 회차에 렉처 파일을 연결할 때는 파일 전체 또는 페이지 범위를 지정한다. 미분류 파일을 연결할 때 Claude가 파일 이름과 내용으로 회차를 제안한다.
- 출결은 회차마다 한 번의 선택으로 기록한다. 기본값은 출석이고, 지각, 결석, 공결로 바꾼다. 결석 상한에 쓰는 결석 횟수는 결석에 `latesPerAbsence`회마다 지각을 결석 1회로 더한 값이며, 공결은 세지 않는다.
- 결석과 공결은 수업 전에 미리 표시할 수 있다. 있는 회차는 회차 메뉴에서 고르고, 아직 없는 다음 강의는 제안 카드의 메뉴에서 "결석으로 표시"나 "공결로 표시"를 고르면 회차를 만들면서 기록한다. 미리 표시한 출결은 그 수업이 시작된 뒤에만 결석 상한 계산과 경고에 센다.

### 강의 녹음

- 회차마다 강의를 녹음하고 기기 안에서 바로 받아쓴다(Speech 프레임워크의 `SpeechTranscriber`, 네트워크를 쓰지 않음). 언어는 녹음을 시작할 때 한국어와 영어 중에서 고른다.
- 녹음은 `Recordings/<회차 이름>.m4a`에, 받아쓰기는 같은 이름의 `.transcript.json`에 저장한다. 같은 회차를 다시 녹음하면 ` 2`, ` 3`을 붙이고 기존 파일은 덮어쓰지 않는다. 녹음 목록(회차, 파일, 시작 시각, 길이, 표시한 지점)은 `course.json`의 `recordings`에 둔다. 녹음은 재생 화면에서 확인을 받은 뒤 오디오와 받아쓰기를 함께 삭제할 수 있다. 녹음 중인 것은 삭제하지 않는다.
- 녹음하는 동안에는 모든 화면 아래에 떠 있는 막대가 들리는 문장, 음량, 경과 시간을 보여 주고, 일시 정지, 지점 표시, 끝내기를 제공한다. 받아쓰기는 문장이 확정될 때마다 몇 초 간격으로 저장해 앱이 중간에 꺼져도 남는다.
- 다시 듣기 화면은 받아쓰기를 시간순으로 보여 주고, 재생 중인 문장을 강조하며 따라 스크롤한다. 문장을 누르면 그 지점부터 재생한다. 받아쓰기 검색, 15초 앞뒤 이동, 재생 속도 1-2배, 받아쓰기 복사를 제공한다.

### 성적 계산

과목의 현재 환산 점수는 다음 순서로 계산합니다.

1. 평가 항목마다 하위 점수를 반영 규칙(`dropLowest`, `bestOf` 등)에 따라 합산해 항목 득점률을 구한다. 면제된 점수는 제외한다.
2. 항목 득점률에 비중을 곱해 더한다.
3. 점수가 하나도 없는 항목은 두 가지 방식으로 보여 준다. 하나는 지금까지 확정된 점수만 반영한 "확보 점수"이고, 다른 하나는 남은 항목에 현재 득점률을 적용한 "예상 점수"다. 예정 횟수를 정하지 않은 여러 회 항목(단일 점수 항목은 1회로 본다)은 얼마나 남았는지 알 수 없으므로 확보 점수에 넣지 않고 예상 점수에만 반영한다.
4. 출결 규칙의 결석 상한을 적용해 받을 수 있는 최대 등급을 표시한다. 결석이 상한에 가까워지면 오늘 화면에 경고를 띄운다.

목표 점수 역산은 남은 평가 항목에서 평균 몇 %를 받아야 사용자가 정한 환산 점수에 도달하는지를 계산합니다. 상대평가 과목은 등급 커트라인을 알 수 없으므로 목표 점수 대신 평균 대비 위치를 보여 줍니다. 공개된 평균과 표준편차로 구한 가중 z 점수를 정규분포에 놓아 상위 몇 %인지 추정하고, 과목의 A 비율(기본 50%, 나머지는 B와 C, 성적 규칙에서 바꿈) 안에 드는지를 정규분포 곡선 위의 표시로 보여 준다. z 값 자체는 보여 주지 않는다. 목표 점수 역산은 절대평가 과목에서 쓴다. 하위 점수에 평균과 표준편차가 있으면 그 점수 줄에 평균에서 떨어진 정도를 `평균 +2.5σ`처럼 보여 줍니다. 평균만 공개되고 표준편차가 없으면 `평균 +8점`처럼 점수 차이로 보여 줍니다. 이런 점수는 같은 과목에서 표준편차가 공개된 점수들의 표준편차/만점 비율을 빌려 z를 추정하고, 곡선의 위치에 `추정`을 붙입니다. 과목에 표준편차가 하나도 없으면 위치는 그리지 않고 가중 평균 차이의 부호만 봅니다. A 비율이 50% 이상인데 평균보다 위면 A 안, 50% 이하인데 평균보다 아래면 A 밖이고, 그 밖의 경우는 표준편차 없이는 알 수 없다고 표시합니다.

### 학점과 GPA 계산

- 학기 GPA는 평어의 `countsInGpa`가 참인 과목만 대상으로 학점 가중 평균을 낸다. S, U, W와 0학점 과목은 제외한다.
- 총 학점은 `countsInCredits`가 참인 과목의 학점 합이다. 유효 학점은 GPA에 들어간 과목의 학점 합이다. 노션 이전 때 노션의 학기 값과 같은 결과가 나오는지 실제 폴더에서 확인한다.
- 누적 GPA는 인정학기를 제외한 모든 학기의 유효 학점으로 계산하고, 인정학기의 학점은 총 학점에만 더한다.
- 전공 GPA는 `countsTowardMajor`가 참인 과목만으로 계산한다.
- 졸업 학점(기본 130)과 평점 하한(기본 2.0), 입학 연도(`admissionYear`)와 선언한 과정(`programs`: 강의 코드 ID와 종류)은 `transcript.json`의 `graduation`에 둔다.
- 재수강 과목의 처리, 졸업 평점 산정 방식, 우등 졸업 기준은 GIST 학칙을 확인해 규칙으로 넣는다. 이 규칙은 `transcript.json`에 설정값으로 두어 학칙이 바뀌어도 코드를 고치지 않게 한다.

### 과제

- 빠른 추가: `선대 HW5 금 23:59`처럼 한 줄로 입력하면 과목, 제목, 마감일을 나눠 저장한다. 과목 이름은 줄 안 어디에 써도 되고, 약칭과 뒤에 붙은 조사(`컴네에다`)를 허용하며, 과목 화면에서 입력하면 과목을 생략할 수 있다. 해석 결과는 저장 전에 입력란 아래에 보여 준다.
- 반복 과제: `보고서 제출 매주 금 23:59`처럼 `매주`를 넣으면 가장 가까운 하나만 만들고 반복을 기억한다. 제출하거나 채점되면 일주일 뒤 같은 시각의 다음 과제가 생기며, 학기 종강일을 넘으면 만들지 않는다. 다음 과제를 지우면 반복이 끝난다.
- 과제의 점수는 평가 항목 하나 또는 묶음 전체로 보낸다. 묶음을 고르면 항목마다 점수 칸이 하나씩 생기고, 만점은 그 항목의 지난 점수에서 가져온다.
- 파일 기반 추가: 과제 문제 PDF가 과목 폴더에 들어오면 Claude가 제목과 마감일을 읽어 과제 등록을 제안한다.
- 과제는 평가 항목과 연결한다. 채점된 점수를 입력하면 그 항목의 하위 점수가 되고, 환산 점수가 바로 갱신된다.
- 제출본이 과목 폴더에 생기면(예: `HW3-5070류현승.pdf`) 과제와 연결하고 상태를 제출로 바꿀지 묻는다.
- 마감 24시간 전과 3시간 전에 알림을 보낸다. 알림 시점은 설정에서 바꾼다.
- LMS 연동은 보류하지만, `source` 필드를 처음부터 두어 나중에 붙여도 데이터 구조를 바꾸지 않게 한다.

### 시험

- 시험은 일시, 장소, 범위 단원, 허용 자료를 가진다. 노션에서 본문에 적던 "Date: 10.20 (Tue) 20:00 \~ 21:30, Location: C104" 같은 정보를 여기에 넣는다.
- 시험마다 시험 종합 정리 노트를 하나 둔다. 범위 단원의 복습 노트를 바탕으로 Claude가 초안을 만들 수 있다.
- 시험 계획은 시험일까지 날짜별 할 일을 담은 타임라인이다. 항목마다 대상(단원, 문제 묶음, 퀴즈 범위)을 지정하면, 해당 작업을 끝낼 때 자동으로 완료 처리된다. Claude에게 남은 날짜와 범위를 주고 계획 초안을 만들게 할 수 있다.

## 복습 스케줄러

복습은 날짜가 아니라 단원을 기준으로 잡습니다. Todoist의 반복 일정은 학습량과 무관하게 돌아가서 밀릴 수밖에 없었고, 밀린 뒤에는 무엇부터 해야 할지 알 수 없었습니다. Folio는 단원마다 다음 복습일을 따로 계산하고, 밀린 단원을 우선순위로 정렬합니다.

### 시작 시점

- 단원의 복습 주기는 그 단원을 다룬 강의 회차의 복습 노트가 만들어진 날 시작한다.
- 복습 노트가 없거나 작성 완료로 표시하지 않았으면 강의 회차 날짜에 시작하고, 첫 복습 항목은 "복습 노트 작성"이 된다.
- 복습 노트는 템플릿으로 만들어진 순간이 아니라 사용자가 "작성 완료"로 표시할 때 다 쓴 것으로 본다. 표시는 노트 툴바, 오늘 화면의 체크, 회차 메뉴에서 하고, 회차 메뉴에서 다시 작성 중으로 되돌릴 수 있다.
- 시험이 없는 교양처럼 복습할 필요가 없는 과목은 과목 편집에서 복습을 끈다(`course.json`의 `reviews: false`). 끈 과목의 단원은 복습 대상이 아니고, 그 회차는 복습 노트가 없는 회차에도 넣지 않는다.
- 한 단원이 여러 회차에 걸치면 마지막 회차를 기준으로 다시 시작한다.

### 간격

기본 간격은 1일, 3일, 7일, 14일, 30일입니다. 복습을 끝낼 때마다 네 가지 결과 중 하나를 고르고, 그에 따라 다음 간격이 정해집니다.

| 결과 | 의미 | 다음 간격 |
| --- | --- | --- |
| 다시 | 내용을 대부분 잊었다 | 1일로 되돌린다 |
| 어려움 | 기억은 했지만 막혔다 | 현재 간격을 한 번 더 쓴다 |
| 보통 | 대체로 기억했다 | 다음 단계로 넘어간다 |
| 쉬움 | 막힘 없이 기억했다 | 한 단계를 건너뛴다 |

- 30일 간격을 "보통" 이상으로 두 번 통과하면 그 단원은 "복습 끝"으로 보고 시험 계획이 있을 때만 다시 올린다.
- 이미 공부한 단원(예: 끝난 시험 범위)은 "건너뛰기"로 바로 "복습 끝"으로 둔다. 복습 화면에서 단원 하나씩, 오늘 화면에서 밀린 단원 전체를 건너뛸 수 있다. `review` 이벤트의 결과 `skip`으로 기록하고, 틀린 카드나 시험 계획이 생기면 다시 올라온다.
- 간격 단계는 설정에서 바꿀 수 있다.
- 단원의 퀴즈에서 틀린 카드가 생기면, 그 단원의 다음 복습일을 다음 날로 앞당기고 간격을 한 단계 낮춘다.
- 시험 범위에 든 단원은 시험 전날을 넘어가는 복습일을 갖지 않도록 조정한다. 시험 7일 전부터는 간격의 상한을 시험까지 남은 날의 절반으로 제한한다.

### 복습 진행

오늘 화면이나 과목 화면에서 단원을 고르면 복습 화면이 열립니다.

1. 그 단원의 복습 노트를 보여 준다. 러프 노트, 필기, 렉처는 옆에 펼쳐 볼 수 있다.
2. 단원에 퀴즈 카드가 있으면 그중 일부를 풀게 한다. 기본은 최근 틀린 카드와 오래 풀지 않은 카드를 합쳐 5장이다.
3. 끝나면 결과를 고른다. 퀴즈를 풀었다면 정답률을 바탕으로 결과를 미리 선택해 둔다.
4. 결과는 `review` 이벤트로 기록하고, 소요 시간은 공부 시간에 더한다.

### 밀린 복습의 우선순위

밀린 단원은 아래 요소를 합산한 점수가 높은 순서로 보여 줍니다.

- 밀린 날수를 현재 간격으로 나눈 값. 짧은 간격에서 밀린 단원일수록 잊었을 가능성이 크다.
- 가장 가까운 시험까지 남은 날. 시험 범위에 든 단원을 앞에 둔다.
- 최근 퀴즈 정답률과 남은 오답 수.

하루 복습 상한을 정해 두면, 상한을 넘는 단원은 우선순위가 낮은 것부터 다음 날로 미룹니다. 미룬 단원과 그 이유는 오늘 화면에 따로 표시합니다.

### 하루 경계

- 하루가 바뀌는 시각을 설정한다. 기본값은 새벽 4시다.
- 앱의 모든 "오늘"은 실제 시각에서 하루 경계만큼 뱀 시각의 날짜다. 새벽 2시에 끝낸 복습과 공부 시간은 전날 기록이 된다.
- 복습일, 공부 시간 집계, 시험 계획 항목의 날짜가 모두 이 기준을 따른다.
- 과제 마감과 시험 일시는 실제 시각을 그대로 쓴다. 마감을 늦게 인식하면 안 되기 때문이다.

## 퀴즈와 채점

중간고사 대비 아티팩트의 퀴즈, AI 채점, 오답 흐름, 손필기 오답 기록을 모두 앱으로 옮기고, 결과를 복습 스케줄러와 연결합니다.

### 카드 만들기

- **노트에서**: 복습 노트나 시험 종합 정리의 정의, 정리, 증명 블록에서 "카드 만들기"를 고르면 Claude가 문제, 모범답, 채점 기준을 만든다. 카드는 원본 블록을 참조하고, 블록이 바뀌면 카드에 "원본 변경됨" 표시를 띄운다.
- **단원에서**: 단원을 고르고 개수와 유형을 정해 한 번에 생성한다. Claude는 그 단원의 노트와 자료를 맥락으로 쓴다.
- **자료에서**: `Exam Review`의 `.tex` 문제집과 해설을 읽어 문제별 카드로 나눈다. `.tex`는 구조가 드러나 있어 PDF보다 정확하게 나눌 수 있다.
- **직접**: 문제와 답을 직접 입력한다.
- 생성된 카드는 바로 넣지 않고 목록으로 보여 준 뒤 사용자가 고른 것만 저장한다.

### 풀기 설정

- 범위: 단원 격자에서 여러 단원을 고른다. 단원마다 카드 수, 진도, 남은 오답 수를 표시한다. "오답만", "시험 범위 전체", "오늘 복습 단원" 같은 바로가기를 둔다.
- 유형: 정의, 정리, 증명, 반례, 계산, 개념, 설계로 걸러 낸다.
- 순서: 단원 순서, 무작위, 오답 우선 중에서 고른다.

### 답하기

- 서술형과 증명은 텍스트로 쓰며, 수식 기호 입력 줄과 LaTeX 입력을 지원한다. 입력하는 동안 수식을 렌더링한 미리보기를 보여 준다.
- iPad에서는 모든 카드를 손글씨로 답할 수 있다. 문제 아래에 필기 영역이 열리고, 답안은 Ink로 저장한다.
- 참거짓과 객관식은 선택하면 바로 채점한다.
- 답하기 전에 힌트를 볼 수 있고, 힌트를 본 기록은 시도에 남긴다.

### AI 채점

- 서술형, 증명, 손글씨 답안은 Claude가 채점한다. 채점에는 문제, 모범답, 채점 기준, 답안을 넘긴다. 손글씨는 이미지로 변환해 넘긴다.
- 채점 결과는 판정(맞음, 애매, 틀림), 빠진 요소 목록, 짧은 피드백으로 구성한다. 손글씨 답안에서는 문제가 되는 줄의 위치도 표시한다.
- 채점 후 모범답을 보여 준다.
- 사용자는 판정을 직접 바꿀 수 있다. 바꾼 기록은 시도에 남기고, 통계에는 바꾼 판정을 쓴다.
- 자기 채점 모드를 제공한다. 모범답을 보고 스스로 판정하는 방식으로, Claude를 쓰지 않는다.
- 같은 카드의 지난 답안과 판정을 시간순으로 볼 수 있다.

### 오답 흐름

- 틀림이나 애매로 판정된 카드는 오답 목록에 들어간다.
- 오답은 다음 날의 복습 항목과 시험 계획에 다시 올라온다.
- 오답 카드를 다시 풀어 맞으면 "해결"로 바뀐다. 해결된 카드는 통계에서 따로 셈다.
- 해결된 카드도 7일 뒤에 한 번 더 확인한다. 이때 다시 틀리면 오답으로 돌아간다.

### 문제 묶음

문제집, 증명집, 족보처럼 종이나 손으로 푸는 문제는 문제 묶음으로 관리합니다.

- 문제 번호 격자에 맞음, 틀림, 해결을 표시한다. 묶음별, 단원별 집계를 보여 준다.
- iPad에서 문제 번호를 고르면 문제지의 해당 페이지와 필기 영역이 함께 열린다. 풀이를 제출하면 Claude가 해설 PDF를 기준으로 채점한다.
- 종이로 푼 문제는 번호를 누르고 판정만 기록한다.
- 틀린 문제는 카드와 같은 오답 흐름을 따른다.

### 통계

- 단원별, 유형별 정답률
- 남은 오답 수와 해결 수
- 날짜별 풀이 수

## 노트 편집기

노트 편집기는 마크다운을 기본으로 하고, 옵시디언에서 쓰던 문법을 그대로 지원하며, 옵시디언에서 부족했던 표와 인터랙티브 요소를 전용 블록으로 추가합니다. Typst는 내보내기에만 씁니다.

### 편집 방식

- 커서가 있는 블록만 원문으로 보이고 나머지는 렌더링된 모습으로 보이는 실시간 미리보기 방식을 기본으로 한다. 전체 원문 보기와 읽기 전용 보기도 제공한다. 실시간 미리보기는 읽기 전용 보기와 같은 간격, 목록 들여쓰기, 콜아웃 제목으로 그린다. 원문의 줄바꿈은 두 보기 모두에서 줄바꿈으로 보인다(옵시디언과 같다). 접힌 콜아웃은 읽기 전용 보기에서만 접힌다. 정리, 보조정리, 따름정리, 명제 바로 아래의 증명은 그 블록에 틈 없이 붙어 보이고, 읽기 전용 보기에서는 접힌 채로 시작한다. 코드 블록은 Python, C/C++, Java, JavaScript/TypeScript, Rust, Go, SQL, Bash, LaTeX를 두 보기에서 같은 색으로 하이라이팅한다. 편집기에 포커스가 없으면 모두 렌더링된 모습으로 보인다.
- `/` 명령으로 블록을 넣는다. 정의, 정리, 증명, 예시, 표, 위젯, 수식, 이미지, 렉처 페이지, 코드, 내부 링크를 제공한다.
- 수식 입력에는 자동 완성과 스니펫을 둔다. 옵시디언에서 latex-suite 플러그인으로 쓰던 방식(예: `mk`로 인라인 수식, `dm`으로 display 수식)을 기본값으로 하고, 스니펫 목록은 설정에서 편집한다.
- 노트 편집 화면 툴바의 연결 메뉴로 노트의 종류와 연결 대상을 함께 정한다. 러프와 복습 노트는 지난 강의 회차를, 시험 종합 정리는 시험을, 단원 정리는 단원(여러 개)을 고르고, 자유 노트는 연결이 없다. 회차에 이미 있던 같은 종류의 노트는 연결에서 빠지고, 종류를 바꾸면 이전 종류의 회차나 시험 연결을 뺀다. 관련 단원(`unitIds`)은 종류를 바꿔도 남긴다. Claude 답으로 만든 노트를 복습 노트로 쓸 때 이 메뉴를 쓴다.
- 노트 목록에서 노트를 우클릭해 "노트 삭제"로 확인을 받고 지운다. 파일은 휴지통으로 옮겨 되살릴 수 있게 하고, 그 노트를 러프나 복습 노트로 쓰던 회차의 연결을 뺀다. 노트의 그림은 다른 노트와 함께 쓸 수 있으므로 `assets/`에 남긴다.
- 이미지를 붙여 넣거나 끌어오면 `Notes/assets/`에 저장하고 그 자리에 링크를 넣는다. 같은 이름의 다른 파일이 있으면 이름 뒤에 번호를 붙이고, 내용이 같으면 있는 파일을 쓴다. 기존 노트가 이미 이 폴더를 쓰고 있어서 노트별 하위 폴더는 두지 않는다.
- 편집기 위쪽의 애셋 트레이는 `Notes/assets/`의 파일을 썸네일로 보여 준다. 썸네일을 본문으로 끌어 놓거나 누르면 링크가 들어가고, Finder에서 트레이로 끌어 오면 폴더에 복사된다.
- iPad에서는 키보드가 없을 때 노트에 손글씨 블록을 넣을 수 있다. 손글씨 블록은 Ink를 참조한다.

### 지원 문법

- 표준 마크다운과 GFM(표, 체크박스, 취소선, 각주)
- 인라인 수식 `$...$`과 display 수식 `$$...$$`. `aligned`, `cases`, `pmatrix` 등 KaTeX가 지원하는 환경을 모두 쓸 수 있다
- 수식 문법은 노트마다 LaTeX와 AsciiMath 중 하나다. frontmatter의 `math: asciimath`가 있으면 AsciiMath로 읽고, 없으면 LaTeX로 읽는다(옵시디언과 노션에서 온 노트). 앱에서 새로 만드는 노트는 설정의 "수식 문법"을 따르며 기본값은 AsciiMath다. AsciiMath는 LaTeX로 바꾼 뒤 KaTeX로 그린다
- 옵시디언 콜아웃 `> [!type] 제목`. 볼트에서 쓰던 definition, theorem, lemma, corollary, proof, example, counterexample, remark, note, tip, warning, important, question, solution, summary, abstract, info, danger를 전부 지원하고, `> [!type]-`로 접힌 상태를 표현한다
- 블록 ID `^def-vectorspace`와 블록 참조
- 노트 간 위키링크 `[[노트 제목]]`, `[[노트 제목#^블록 ID|표시 문구]]`. 저장할 때는 노트 ID를 함께 기록해 제목이 바뀌어도 연결이 유지되게 한다
- 노트 안 임베드 `![[노트 제목#제목]]`
- 앱 내부 객체 링크: 단원, 강의 회차, 자료의 특정 페이지, 퀴즈 카드, 과제. 예를 들어 `[[material:<ID>#page=12]]`는 렉처 12쪽을 연다
- 옵시디언 볼트 링크 `obsidian://open?vault=Brain&file=...`. 누르면 옵시디언이 열린다

### 수학 블록

- 정의, 정리, 보조정리, 따름정리, 예시, 반례 콜아웃에는 노트 안에서 자동 번호를 붙인다. 교재 번호를 직접 적으면(예: `Theorem 1.20`) 그 번호를 쓴다.
- 증명 콜아웃을 정리 바로 아래에 두면 그 정리에 속한 증명으로 보고, 기본으로 접어 둔다.
- 블록 참조로 다른 정리를 인용하면, 마우스를 올리거나 길게 눌렀을 때 본문을 미리 보여 준다.
- 블록마다 "카드 만들기"와 "Claude에게 물어보기"를 둔다.

### 표 블록

마크다운 표는 한 행을 한 줄에 써야 해서 셀 병합, 셀 안의 줄바꿈과 목록, 열 너비를 표현할 수 없습니다. 그래서 전용 표 블록을 둡니다.

- 스프레드시트처럼 셀을 선택해 편집한다. 행과 열 추가와 삭제, 이동, 셀 병합, 열 너비, 정렬, 머리행과 머리열을 화면에서 바로 조작한다.
- 각 셀은 작은 마크다운 문서다. 수식, 목록, 줄바꿈, 링크를 넣을 수 있다.
- 파일에는 `cb-table` 코드 블록 안에 JSON으로 저장한다. 병합이 없는 단순한 표는 일반 마크다운 표로 저장하고, 병합이나 셀 안 목록이 생길 때만 전용 형식으로 바꾼다.
- 표를 퀴즈로 쓸 수 있다. 열이나 셀을 가리고 맞히는 방식으로, 비교표를 암기할 때 쓴다.

### 위젯 블록

LR 오토마톤 스테퍼나 Petersen Graph처럼 노트 안에서 직접 조작하는 자료를 넣는 블록입니다.

- 노트에는 `cb-widget` 코드 블록에 위젯 ID와 표시 높이만 남기고, 실제 HTML은 `.folio/widgets/`에 파일로 둔다.
- 노트를 쓰다가 Claude에게 위젯을 요청하면 HTML을 생성하고 미리보기를 보여 준 뒤, 사용자가 승인하면 저장한다. 수정 요청도 같은 방식으로 처리한다.
- 위젯은 격리된 `WKWebView`에서 실행한다. 네트워크 접근은 막고, 앱과는 메시지로만 통신한다. 위젯이 쓸 수 있는 메시지는 자기 데이터 읽기와 저장, 퀴즈 결과 기록, 앱 테마 조회로 제한한다.
- 자주 쓰는 형태는 기본 위젯 템플릿으로 둔다. 데이터만 바꿔 다시 쓰므로 매번 새로 생성하지 않는다.
  - 그래프 그리기와 탐색 알고리즘 단계 보기
  - 상태 기계와 오토마톤 단계 실행
  - 행렬 연산과 행 연산 단계 보기
  - 함수와 매개변수 슬라이더 그래프
  - 자료구조 삽입과 삭제 애니메이션
- 테마 색과 글꼴을 앱에서 넘겨받아 라이트 모드와 다크 모드에 맞춘다.

### 노트 템플릿

| 종류 | 기본 구성 |
| --- | --- |
| 러프 | 빈 본문. 수업 중 빠르게 쓰는 용도이므로 구조를 강제하지 않는다 |
| 복습 | 이번 회차의 단원, 핵심 정의와 정리, 예시, 모르는 것 |
| 시험 종합 정리 | 시험 범위, 단원별 요약, 자주 틀리는 것, 공식과 정리 모음 |
| 단원 정리 | 정의, 정리와 증명, 예시와 반례, 관련 단원 |

템플릿은 설정에서 고칠 수 있습니다. Claude가 노트를 쓸 때는 사용자가 정해 둔 노트 작성 규칙을 따릅니다. 예를 들어 정의는 전제, 조건, 결론 순서로 쓰고, 수학적 진술은 영어와 기호로, 설명은 한국어로 쓰며, display 수식은 하나씩 나눠 씁니다. 이 규칙은 설정의 "노트 작성 규칙"에 텍스트로 저장하고, Claude에 맥락을 넘길 때 항상 포함합니다.

## 손필기

손필기는 iPad에서 PencilKit으로 앱 안에 직접 합니다. PDF 위에 덧쓰지 않고 앱이 만든 필기 페이지에 쓰며, 렉처는 나란히 띄워 둡니다. 원본 PDF는 수정하지 않습니다.

### 필기 문서

- 필기 문서는 강의 회차, 단원, 퀴즈 답안, 문제 풀이 중 하나에 속한다. 어느 것에도 속하지 않는 자유 필기도 만들 수 있다.
- 종이는 무지, 줄, 모눈, 점 중에서 고른다. 페이지는 아래로 끊김없이 이어지고, 내보낼 때만 A4 크기로 나눈다.
- 필기 도구는 PencilKit의 기본 도구(펜, 마커, 연필, 지우개, 올가미, 자)를 쓴다. 자주 쓰는 펜 색과 굵기는 즐겨찾기로 저장한다.
- 필기는 획 단위의 `PKDrawing`으로 저장해 확대하거나 일부를 고쳐도 화질이 유지된다.

### 렉처와 나란히 쓰기

- 화면을 좌우로 나눠 한쪽에는 렉처나 족보 PDF를, 다른 쪽에는 필기를 띄운다. 두 쪽의 비율은 조절할 수 있다.
- 강의 회차의 필기를 열면 그 회차에 연결된 렉처가 자동으로 옆에 열린다.
- 렉처에서 영역을 선택해 필기 쪽으로 끌어오면 이미지로 들어간다. 이미지는 원본 파일과 페이지를 기억하고, 누르면 원본의 해당 페이지로 이동한다.
- 필기하는 동안 렉처 페이지를 넘기면, 필기의 현재 위치에 그 페이지 번호를 작게 기록해 둔다. 나중에 필기의 어느 부분이 렉처 몇 쪽에 해당하는지 찾을 때 쓴다.

### Mac에서의 필기

- Mac에서는 필기를 보기만 한다. 확대, 검색, 내보내기, Claude에 넘기기는 가능하다.
- 필기 텍스트 검색을 위해 iPad에서 저장할 때 손글씨 인식 결과를 함께 저장한다. 인식에는 Vision 프레임워크를 쓰고, 수식은 인식하지 않는다.

### 채점과 Claude 연동

- 퀴즈와 문제 풀이의 손글씨 답안은 제출할 때 이미지로 변환해 Claude에 넘긴다. 변환 해상도는 긴 변 기준 2,000픽셀로 하고, 길면 여러 장으로 나눈다.
- 강의 회차의 필기는 복습 노트 초안을 만들 때 맥락으로 넘길 수 있다.
- Claude 패널에서 필기의 일부를 올가미로 선택해 질문할 수 있다. 예를 들어 증명의 한 줄을 골라 "여기서 왜 이 부등식이 성립하는가"를 묻는다.

### 기존 노타빌리티 필기

기존 필기는 변환하지 않고 노타빌리티에서 PDF로 내보내 과목 폴더의 Archive에 둡니다. 앱은 이 PDF를 "이전 필기" 역할의 자료로 다루고, 강의 회차나 단원에 연결할 수 있게 합니다.

## Claude 연동

Claude는 과목마다 맥락이 자동으로 주어지는 공부 도우미이자, 채점과 분류와 초안 작성을 맡는 작업자입니다. Claude가 만든 결과물은 항상 사용자가 확인한 뒤에 저장합니다.

### 호출 방식

연동 계층을 추상화해 두 가지 방식을 모두 지원합니다. 플랫폼마다 쓸 수 있는 방식이 다릅니다.

| 방식 | Mac | iPad | 비용 | 비고 |
| --- | --- | --- | --- | --- |
| Claude Code CLI를 하위 프로세스로 실행 | 가능(기본) | 불가 | 기존 구독 | 과목 폴더를 작업 디렉터리로 지정한다. 도구를 모두 끄고 답만 받으므로 Claude가 파일을 읽거나 바꾸지 않는다. 구독 호출은 API 사용량과 비용에 넣지 않는다 |
| Claude API 직접 호출 | 가능 | 가능 | 사용량만큼 과금 | API 키는 키체인에 저장하고 iCloud 키체인으로 두 기기가 공유한다 |

- iPad는 프로세스를 실행할 수 없으므로 API만 쓸 수 있다. 구독만 쓰고 싶다면 iPad의 요청을 같은 네트워크의 Mac이 대신 처리하는 중계 모드를 두는 방안이 있다. 중계 모드는 Mac이 켜져 있어야 동작한다.
- 작업 종류별로 모델을 따로 정한다. 파일 분류처럼 가벼운 작업은 작은 모델을, 채점과 증명 검토는 큰 모델을 기본값으로 한다.

### 맥락 구성

Claude에 넘기는 맥락은 요청마다 아래 순서로 자동으로 모읍니다. Claude 프로젝트에 자료를 따로 올리지 않아도 됩니다.

1. 과목 요약: 과목명, 단원 목록, 현재 진도, 다가오는 시험과 범위, 과목 메모
2. 사용자 규칙: 설정의 노트 작성 규칙과 답변 언어
3. 현재 화면의 대상: 열려 있는 노트, 필기, 렉처 페이지, 퀴즈 카드
4. 관련 자료: 현재 단원에 연결된 복습 노트와 자료. PDF는 PDFKit으로 추출한 텍스트를 쓰고, 텍스트가 없거나 그림이 중요한 페이지는 이미지로 넘긴다
5. 검색 결과: 교재처럼 큰 자료는 통째로 넣지 않고, 질문과 관련된 페이지를 검색해 그 페이지만 넣는다

- 맥락에 들어간 항목은 Claude 패널에 목록으로 보여 주고, 사용자가 빼거나 더할 수 있다.
- 맥락에 넣은 노트가 품은 그림(`![](…)`, `![[…]]`)은 긴 변 1,568픽셀의 JPEG로 줄여 노트 글 뒤에 이름과 함께 넘긴다. 과목 폴더 밖의 파일은 넘기지 않는다. 패널의 항목에 그림 수를 표시한다.
- 맥락이 모델의 한도를 넘으면 위 목록의 뒤쪽부터 줄이고, 줄인 사실을 패널에 표시한다.
- CLI 방식에서는 과목 폴더를 작업 디렉터리로 주고, 맥락 요약을 `.folio/CONTEXT.md`로 써 두어 Claude가 필요한 파일을 직접 읽게 한다. 쓰기 권한은 `Notes, Ink, Exams, .folio` 폴더로 제한한다.

### 대화

- 대화는 과목마다 따로 저장한다. 과목 안에서도 주제별로 여러 대화를 만들 수 있다.
- 대화에서 나온 내용을 열린 노트에 넣거나, 새 노트로 만들거나, 퀴즈 카드로 만들 수 있다. 새 노트의 제목은 답의 첫 `#` 제목이고, 없으면 대화 제목이다.
- 답은 쓰이는 대로 보여 준다. 구독(CLI) 방식은 쓰는 중인 글을 0.5초마다 갱신하고, API 방식은 다 받은 뒤 보여 준다.
- 답변의 수식은 노트와 같은 렌더러로 그린다.
- 대화 기록은 claude.ai의 대화 기록에 남지 않는다.

### 작업 목록

| 작업 | 입력 | 결과 |
| --- | --- | --- |
| 질문과 설명 | 대화와 맥락 | 답변 |
| 복습 노트 초안 | 러프 노트, 필기, 회차의 렉처 | 복습 노트 초안 |
| 시험 종합 정리 초안 | 범위 단원의 복습 노트, 오답 기록 | 종합 정리 초안 |
| 퀴즈 카드 생성 | 노트 블록, 단원, `.tex` 문제집 | 카드 후보 목록 |
| 채점 | 문제, 모범답, 채점 기준, 답안 | 판정, 빠진 요소, 피드백 |
| 파일 분류 | 파일 이름, 첫 페이지 텍스트, 과목 구조 | 역할, 종류, 연결할 회차와 단원 |
| 과제 추출 | 과제 PDF | 제목, 마감일 |
| 평가 기준 추출 | 강의계획서, OT 자료 | 평가 항목, 비중, 반영 규칙, 출결 규칙 |
| 시험 계획 | 시험 범위, 남은 날, 단원별 상태 | 날짜별 계획 초안 |
| 위젯 생성 | 요청 문장, 단원 맥락 | HTML 위젯 |

- 구조화된 결과가 필요한 작업(채점, 분류, 추출)은 JSON 스키마를 지정해 응답을 받는다. 스키마에 맞지 않는 응답은 한 번 다시 요청하고, 그래도 실패하면 사용자에게 알린다.
- 파일을 만들거나 바꾸는 작업은 변경 내용을 미리 보여 주고 승인을 받는다.

### 데이터 전송 원칙

- Claude로 데이터를 보내는 것은 사용자가 직접 요청한 작업과, 설정에서 켜 둔 자동 작업(미분류 파일 분류 등)뿐이다.
- 자동 작업도 파일을 옮기거나 바꾸지는 않고 제안만 만든다.
- API 사용량과 예상 비용을 설정 화면에서 월별로 보여 준다.

## 부가 기능

### 공부 시간

- 과목 화면, 노트, 필기, 퀴즈, 복습 화면이 앞에 열려 있는 동안의 시간을 그 과목의 공부 시간으로 자동 기록한다.
- 입력이 5분 동안 없거나 앱이 백그라운드로 가면 기록을 멈춘다. PDF를 읽는 중에는 페이지 이동이 없어도 15분까지 인정한다.
- 수동 타이머도 제공한다. 종이로 공부할 때처럼 앱 밖에서 한 공부를 기록하는 용도다.
- 기록은 하루 경계를 기준으로 날짜에 넣고, 오늘 화면과 성적 화면에서 날짜별, 과목별로 보여 준다.
- 두 기기에서 같은 시간에 기록이 겹치면 한 번만 센다.

### 자료 보기

- PDF는 앱 안의 뷰어로 연다. 페이지 썸네일, 본문 검색, 마지막으로 본 페이지 기억을 지원한다.
- PDF 페이지에서 바로 노트 링크를 복사하거나, 그 페이지를 맥락으로 지정해 Claude에게 질문할 수 있다.
- PDF 외의 형식(docx, pptx, hwp, xlsx, 코드)은 Quick Look으로 미리 보고, 기본 앱으로 연다.
- 코드 프로젝트 폴더는 Finder나 설정한 편집기로 연다.

### 검색

- 모든 과목의 노트 본문, 자료 이름과 PDF 본문, 퀴즈, 과제, 강의 회차를 검색한다.
- 검색 색인은 기기별 로컬 SQLite의 FTS5로 만들고, 파일이 바뀔 때 갱신한다.
- 과목, 학기, 종류로 걸러 낼 수 있다.

### 알림

- 과제 마감 전(기본 24시간, 3시간)
- 시험 전날과 당일 아침
- 오늘 복습할 단원 수. 하루 한 번, 설정한 시각에 보낸다
- 결석이 상한에 한 번 남았을 때
- 알림은 종류별로 끌 수 있다

### 내보내기

- 노트, 시험 종합 정리, 단원 묶음을 Typst를 거쳐 PDF로 만든다. 만든 PDF는 용도에 맞는 곳에 저장한다. 시험 종합 정리는 해당 시험 폴더에 `Summary.pdf`로, 그 밖의 노트는 `Notes/Exports`에 둔다.
- 마크다운을 Typst 문법으로 변환하는 변환기를 둔다. 콜아웃은 상자로, 표 블록은 병합과 정렬을 유지한 Typst 표로 바꾼다. 수식은 LaTeX을 Typst 수식으로 변환하는 라이브러리를 쓰고, 변환하지 못한 수식은 이미지로 넣는다.
- 위젯 블록은 현재 화면을 이미지로 캡처해 넣는다.
- 필기는 PDF로 내보낼 수 있다. A4로 페이지를 나누고, 잘라 붙인 렉처 조각도 포함한다.
- 내보낸 PDF는 iPad에서 바로 열어 필기의 배경으로 쓸 수 있다.

## 명령줄 도구

Mac의 명령줄 도구 `folio`는 앱에서 할 수 있는 데이터 조작을 모두 터미널에서 할 수 있게 합니다. 사람이 터미널에서 쓰기도 하지만, 주된 사용자는 Claude Code 같은 에이전트입니다. 에이전트가 JSON 파일을 직접 고치면 앱이 지키는 규칙(양방향 연결, 폴더 생성, 로그, 원자적 쓰기)을 빠뜨리기 쉬우므로, 에이전트는 항상 이 도구를 거쳐 데이터를 바꿉니다.

### 액션

- 데이터를 바꾸는 일은 모두 **액션**으로 정의한다. 액션은 이름, 입력, 결과를 가진 하나의 동작이다. 예를 들어 "시험 추가"는 Exam을 만들고, 성적 항목과 범위 단원을 연결하고, 시험 폴더를 만들고, 수정 시각과 기기 ID를 남기는 것까지가 한 액션이다.
- 앱의 화면과 명령줄 도구는 같은 액션 구현을 호출한다. 화면은 파일이나 `course.json`의 값을 직접 바꾸지 않는다. 같은 입력이면 앱에서 하든 명령줄에서 하든 결과 파일이 같다.
- 액션 목록은 한 곳에서 정의한다. 앱의 모든 액션은 명령줄 명령을 가져야 하며, 명령이 없는 액션이 있으면 테스트가 실패한다.
- 액션은 선언 하나에서 입력 형식, 명령줄 명령, 도움말, 확인 문구, 완료 문구를 만든다. 지우기와 옮기기는 항상 확인을 받는다.
- 지켜야 할 규칙(값의 범위, 비어 있으면 안 되는 제목, 가리키는 항목이 있는지, 양방향 연결)은 데이터 모델에 한 번 선언하고, 모든 저장이 그 규칙으로 검사한다. 저장으로 새 위반이 생기면 저장하지 않고 이유를 알린다. 이미 있던 위반은 저장을 막지 않는다. 앱은 같은 규칙으로 버튼을 끄거나 숨기고, 막힌 이유를 보여 준다.
- 화면 상태(창, 사이드바 펼침, 탭, 외관), 녹음과 받아쓰기, 필기 획 편집, 노트 편집기 안의 편집 동작은 액션이 아니다. 노트 본문은 파일 단위로 읽고 쓴다(`folio note show`, `folio note write`).
- Claude를 부르는 액션(채점, 초안 만들기, 분류 제안)도 같은 Claude 연동 계층을 쓰고, 결과는 앱에서처럼 제안으로만 저장한다.

### 명령 구조

`folio <대상> <동작> [인자] [옵션]` 형식입니다. 대상은 데이터 모델의 엔티티이고, 동작은 대상마다 같은 이름을 씁니다.

| 동작 | 뜻 |
| --- | --- |
| `list` | 목록. 필터 옵션을 받는다 |
| `show` | 한 항목의 자세한 내용 |
| `add` | 만들기 |
| `set` | 필드 바꾸기. 바꿀 필드만 옵션으로 준다 |
| `rm` | 지우기. 노트와 파일은 휴지통으로 옮긴다 |
| 대상 고유 동작 | 예: `session note-done`, `exam scope`, `unit link`, `review record`, `quiz grade` |

- 대상: `semester`, `course`, `session`, `unit`, `exam`, `assignment`, `score`, `component`, `attendance`, `material`, `note`, `ink`, `review`, `quiz`, `problem-set`, `catalog`, `transcript`, `requirement`, `settings`.
- 여러 대상에 걸친 명령: `today`(오늘 화면과 같은 요약), `search`, `gpa`, `check`(구조 검사), `cleanup`(기존 폴더 정리), `import`(노션, 캘린더, 단원 같은 일회성 가져오기), `backup`.
- 항목은 사람이 읽는 이름으로 가리킨다. 과목은 강의 코드(`EC4207`)나 폴더 이름, 회차는 `9주차-1`, 시험은 제목(`Quiz1`), 단원은 제목으로 가리키며, UUID도 받는다. 이름이 여러 항목에 맞으면 실행하지 않고 후보를 보여 준다.
- 학기를 생략하면 현재 학기를 쓴다.
- 도움말과 fzf 지원은 아래 두 절을 따른다.

### 도움말

- `folio`나 `folio help`는 명령을 쓰임새별로 묶어 보여 준다. 묶음은 오늘, 수업(회차, 단원, 출결), 시험과 과제, 성적(점수, 성적 항목, 성적표, 졸업 요건), 복습과 퀴즈, 자료와 노트, 설정과 카탈로그, 가져오기와 점검이다. 명령마다 한 줄 설명을 붙이고, 맨 아래에 자주 쓰는 예시 몇 개와 `folio help <주제>` 안내를 둔다.
- `folio <대상> --help`는 그 대상의 동작 목록을, `folio <대상> <동작> --help`는 설명, 사용법, 인자, 옵션, 예시, 관련 명령을 순서대로 보여 준다.
  - 인자와 옵션마다 받는 값의 형식과 기본값을 쓴다. 정해진 값 중에서 고르는 옵션은 고를 수 있는 값을 모두 쓴다.
  - 예시는 실제 데이터처럼 쓴 명령 두세 개와 각각이 하는 일 한 줄이다.
  - 쓰기 명령은 `--dry-run`, 확인이 필요한지, 무엇이 바뀌는지(만들어지는 폴더, 바뀌는 연결)를 적는다.
- `folio help <주제>`는 명령이 아닌 개념을 설명한다. 주제는 가리키기(과목, 회차, 시험을 이름으로 가리키는 규칙), 출력(`--json` 형식과 오류 형식), 종료 코드, 안전(미리보기, 확인, 되돌리기), fzf다.
- 도움말도 사람용 출력 규칙을 따른다. 묶음 제목은 굵게, 설명은 흐리게, 예시의 명령은 그대로 복사해 실행할 수 있게 쓴다.
- 없는 명령이나 옵션을 쓰면 가장 비슷한 것을 제안한다(`exam ad` → `exam add`).
- `folio help --json`은 모든 명령, 인자, 옵션, 값의 형식, 예시를 기계가 읽을 수 있게 내보내서 에이전트가 명령을 찾을 수 있게 한다.
- 도움말의 예시는 테스트가 가짜 GIST 폴더 사본에서 실제로 실행한다. 쓰기 명령의 예시는 `--dry-run`으로 실행한다. 예시가 실패하면 테스트가 실패한다.

### fzf와 셸 완성

[fzf](https://github.com/junegunn/fzf)로 항목을 골라 명령에 넘길 수 있게 합니다. fzf는 사용자가 따로 설치한 프로그램이며, 없어도 모든 명령이 동작합니다.

- **고르기**: 터미널에서 항목 인자를 빼고 실행하면, fzf가 있을 때 그 대상의 목록을 fzf로 띄워 고르게 한다. 오른쪽 미리보기 창에는 고른 항목의 `show` 출력을 보여 준다. 이름이 여러 항목에 맞을 때(종료 코드 3)도 터미널이면 후보를 fzf로 띄운다. 여러 개를 받는 인자(범위 단원, 연결 회차)는 여러 개를 고르게 한다.
- 표준 입력이나 표준 출력이 터미널이 아니거나 `--json`, `--no-pick`, `FOLIO_NO_PICK`이 있으면 fzf를 띄우지 않고 사용법 오류를 낸다. 에이전트가 쓸 때 입력을 기다리며 멈추지 않게 하기 위해서다.
- **줄 형식**: 모든 `list`는 `--lines`를 받는다. 머리글 없이 한 항목을 한 줄로, 탭으로 나눠 쓴다. 첫 칸은 다른 명령에 그대로 넘길 수 있는 참조(`EC4207/Quiz3`, `EC4207/9주차-1`)이고, 나머지 칸은 사람이 읽는 내용이다. 색은 `--lines --color`일 때만 쓴다. 직접 fzf를 조합할 때 쓴다.

  ```
  folio exam list --lines | fzf --delimiter '\t' --with-nth 2.. --preview 'folio exam show {1}' | cut -f1 | xargs folio exam show
  ```

- **셸 완성**: `folio completion zsh|bash|fish`는 셸 완성 스크립트를 낸다. 명령과 옵션뿐 아니라 강의 코드, 회차 이름, 시험 제목, 단원 제목, 성적 항목 같은 값도 실제 데이터에서 완성한다. 값 후보에는 설명(과목 이름, 날짜)을 붙여서 fzf-tab 같은 완성 플러그인에서 읽기 좋게 한다.
- `folio help fzf`는 위 사용법과 fzf 기본 옵션(`FOLIO_FZF_OPTS`)을 설명한다.

### 출력

- 기본 출력은 사람이 읽기 좋은 형식이다. 아래 "사람용 출력" 절을 따른다.
- 모든 명령은 `--json`을 받는다. 이때 표준 출력에는 JSON 값 하나만 쓰고, 진행 표시나 안내 문구를 섞지 않는다. 필드 이름은 `course.json`과 같은 이름을 쓰고, 날짜는 ISO 8601로 쓴다.
- 쓰기 명령의 결과는 바뀐 항목과 함께, 만들거나 옮긴 파일 경로를 담는다.
- 오류는 표준 오류에 쓴다. `--json`이면 `{"error": {"code", "message", "candidates"}}` 형식이다. 종료 코드는 아래와 같다.

| 종료 코드 | 뜻 |
| --- | --- |
| 0 | 성공 |
| 1 | 예기치 못한 오류 |
| 2 | 사용법 오류 |
| 3 | 대상을 찾지 못했거나 여러 개에 맞음 |
| 4 | 규칙 위반(전공 과목의 S/U, 끝이 시작보다 이른 시험 등) |
| 5 | 확인이 필요한데 `--yes`가 없음 |
| 6 | 다른 곳에서 바뀌어 충돌함 |
| 7 | 커버리지 검사 실패 |

### 사람용 출력

앱 화면의 정보를 터미널에 옮긴 것처럼 보이게 합니다. 같은 정보를 같은 순서와 같은 말로 보여 주고, 앱의 상태 문구(`복습 끝`, `복습 노트 마저 쓰기`, `2일 밀림`)를 그대로 씁니다.

- **머리줄**: 과목에 딸린 명령은 첫 줄에 과목 색 점, 과목 이름, 강의 코드와 교수를 쓴다. `today`는 날짜, 학기, 하루 경계를 쓴다.
- **표**: 목록은 머리글 줄을 흐리게 쓴 표로 보여 준다. 테두리 선은 쓰지 않고 열 간격으로 맞춘다. 한글과 한자는 두 칸으로 세어 열을 맞추고, 터미널 너비를 넘는 칸은 끝을 `…`로 줄인다. 이름 열은 줄이지 않고 설명 열부터 줄인다.
- **한 항목**: `show`는 이름과 값 쌍으로 쓰고, 연결된 항목(범위 단원, 연결 회차, 점수)은 그 아래 들여 쓴 목록으로 쓴다.
- **트리**: 단원과 졸업 요건 분류처럼 계층이 있는 것은 `├─`, `└─`로 그린다. `--depth`로 깊이를 정한다.
- **막대**: 성적 항목의 비율, 수업 진행, 복습 진행은 `█░`나 `▰▱` 막대로 보여 준다. 막대 옆에 숫자를 함께 써서 색이나 모양 없이도 읽히게 한다.
- **색**: 상태 색은 터미널의 기본 16색(초록 성공, 노랑 경고, 빨강 위험, 흐림 보조)을 써서 밝은 터미널과 어두운 터미널 모두에서 읽히게 한다. 과목 강조색은 `course.json`의 색을 쓰되, 트루컬러를 지원하지 않는 터미널에서는 가장 가까운 256색으로 바꾼다. 과목 강조색은 점(`●`)과 막대에만 칠하고 이름 글자에는 칠하지 않는다. 상태 색은 상태 문구(`2일 밀림`, `오늘 오후 11:59`)에 칠한다.
- **날짜와 시각**: 가까운 것은 상대 날짜(`내일`, `D-7`, `33일 후`)를, 먼 것은 `11월 30일 (월)`을 쓴다. 시각은 시스템의 12/24시간 설정을 따른다. 지난 항목은 흐리게 쓴다.
- **쓰기 결과**: 첫 줄에 `✓`와 한 일을 쓰고, 바뀐 필드는 `이전 → 이후`로, 만든 파일과 폴더는 경로로 쓴다. `--dry-run`은 첫 줄에 "미리보기"를 쓰고 `+` 추가, `~` 변경, `-` 삭제로 표시한다.
- **확인**: 확인이 필요한 명령은 무엇이 바뀌는지 한 문장으로 말하고 `[y/N]`으로 묻는다. 기본값은 아니오다.
- **오류**: 첫 줄에 `✗`와 무엇이 잘못됐는지 쓰고, 그 아래 후보나 고칠 방법을 실행할 수 있는 명령으로 쓴다.
- **꼬리줄**: 목록 끝에 개수와 숨긴 항목을 보는 옵션을 흐리게 쓴다(`6개 · --all로 취소된 것까지`).
- **파일 경로**: 터미널이 지원하면 하이퍼링크로 써서 누르면 Finder나 기본 앱으로 열린다.
- 출력이 터미널이 아니거나 `NO_COLOR`가 있으면 색과 하이퍼링크를 끄고 배치는 그대로 둔다. 진행 표시는 터미널일 때만 표준 오류에 쓴다.

### 커버리지 검사

앱과 명령줄 도구가 같은 일을 한다는 것을 사람이 기억에 기대지 않고 검사로 확인합니다.

- `folio actions`는 모든 액션을 표로 보여 준다. 열은 액션 이름, 명령줄 명령, 앱에서 부르는 화면, 동등성 테스트 유무다.
- `folio actions --check`는 아래 중 하나라도 있으면 실패한다(종료 코드 7). 모두 `--json`으로도 낸다.
  - 명령줄 명령이 없는 액션
  - 동등성 테스트가 없는 액션. 동등성 테스트는 같은 가짜 GIST 폴더 사본에 앱이 부르는 경로와 명령줄 명령으로 각각 액션을 실행하고, 결과 파일이 같은지(수정 시각과 기기 ID는 빼고) 비교한다
  - 앱 코드에서 액션을 거치지 않고 `course.json`의 값이나 GIST 폴더의 파일을 바꾸는 곳. 소스를 검사해서 찾고, 파일과 줄을 알려 준다
- 앱이 부르지 않는 액션(명령줄 전용, 가져오기 같은 일회성 작업)은 실패가 아니라 따로 표시한다.
- 끝에 요약을 쓴다. 예: `액션 84개 · 명령 84/84 · 동등성 테스트 80/84 · 액션 밖 변경 0곳`.
- `mise run test`는 이 검사를 함께 돌린다.

### 에이전트용 호출

에이전트가 MCP 도구를 부르듯 액션을 부를 수 있게 합니다. MCP 서버 없이 명령줄 도구만으로 됩니다.

- `folio actions --schema`는 모든 액션의 이름, 한 줄 설명, 입력 형식(JSON Schema), 결과 형식을 JSON 하나로 낸다. 입력 형식은 액션 구현의 입력 타입에서 만들어서 따로 관리하지 않는다. 항목을 가리키는 필드는 UUID와 사람이 읽는 이름(`EC4207`, `9주차-1`)을 모두 받는다고 적는다.
- `folio run <액션> --input '<JSON>'`은 액션 하나를 실행한다. `--input -`이면 표준 입력에서 읽는다. 입력이 형식에 맞지 않으면 어느 필드가 왜 틀렸는지 알려 주고 종료 코드 2로 끝난다. `--dry-run`, `--yes`, `--json`은 다른 명령과 같다.
- `folio run`과 `<대상> <동작>` 명령은 같은 액션을 같은 입력으로 부른다. 동등성 테스트가 이를 확인한다.
- `folio help <하고 싶은 일>`은 자연어로 명령을 찾는다. 명령 이름이나 도움말 주제가 아닌 낱말이 오면 검색으로 본다. 명령마다의 도움말, 옵션 설명, 예시와 일상어 대응표(`할 일`→과제, `지우기`→`rm`)로 순위를 매겨 명령, 관련 옵션, 예시를 보여 주고, `--json`이면 같은 내용을 JSON으로 낸다. 에이전트가 명령 이름을 몰라도 요청에서 명령으로 갈 수 있게 하기 위해서다.
- 에이전트 스킬 `folio`(SKILL.md)는 특정 에이전트에 묶이지 않는 공개 Agent Skills 형식으로 쓰고, 원본을 `folio`가 가진다. `folio skill`은 내용을 보여 주고, `folio skill --install <스킬 폴더>`는 그 폴더에 `folio/SKILL.md`를 쓴다(Claude Code는 `~/.claude/skills`, 다른 에이전트는 각자의 스킬 폴더). 저장소의 `.claude/skills/folio/SKILL.md`는 같은 내용의 사본이며 테스트가 둘이 같은지 확인한다. 스킬은 Folio 데이터를 바꿀 때 JSON 파일을 직접 고치지 않고 `folio`를 쓰라는 규칙, 자주 하는 일의 명령 예시, 명령을 찾는 법(`folio help <자연어>`, `folio help --json`, `folio actions --schema`), 이동·삭제에는 사용자 승인 뒤에만 `--yes`를 붙인다는 안전 규칙을 담는다. 스킬의 예시 명령도 도움말의 예시처럼 테스트가 가짜 GIST 폴더 사본에서 실행한다.
- 저장소 밖에서 일하는 에이전트도 쓸 수 있게 `mise run install-cli`가 `folio`를 `~/.local/bin`에 설치한다.

### 쓰기와 안전

- 모든 쓰기 명령은 `--dry-run`을 받는다. 실제로 쓰지 않고, 바뀔 항목과 만들어질 파일을 보여 준다.
- 파일 이동, 이름 변경, 삭제, 여러 항목을 한 번에 바꾸는 명령은 확인을 받는다. 터미널이면 묻고, 아니면 `--yes`가 있어야 실행한다. 에이전트는 사용자의 승인을 받은 뒤에만 `--yes`를 붙인다. 이동과 이름 변경은 `.folio/moves.jsonl`에 남긴다.
- 쓰기는 앱과 같은 저장 계층을 거친다. `NSFileCoordinator`로 원자적으로 쓰고, 모르는 필드를 보존한다.
- 명령줄 도구는 Mac의 앱과 다른 기기 ID를 가진다. 기기별 로그에 앱과 동시에 쓰지 않게 하기 위해서다. ID는 처음 실행할 때 만들어 사용자 설정 폴더에 둔다.
- 앱이 켜져 있어도 명령줄 도구를 쓸 수 있다. 앱은 `NSFilePresenter`로 바깥에서 바뀐 파일을 감지해 다시 읽는다. 앱에서 고치던 항목이 바깥에서도 바뀌었으면 동기화와 충돌 방지 절의 규칙대로 항목 단위로 병합한다.
- GIST 폴더는 `--gist` 옵션, 환경 변수 `FOLIO_GIST`, 앱이 지정한 폴더 순으로 정한다.
- 테스트는 가짜 GIST 폴더를 쓴 임시 폴더에 명령을 실행해서, 앱의 같은 액션과 결과 파일이 같은지 확인한다.

### 기존 명령의 정리

지금의 일회성 명령(`check`, `cleanup`, `import-notion`, `import-notes`, `track`, `import-calendar`, `import-exams`, `import-units`, `exam-scope`, `import-requirements`, `import-handbook`, `gpa`)은 위 구조로 옮긴다. 예를 들어 `import-exams`는 `import exams`, `exam-scope`는 `exam scope`가 된다. 옛 이름은 남기지 않는다.

## 기존 데이터 이전

이전은 앱에 넣는 일회성 가져오기 도구로 수행합니다. 가져오기는 먼저 결과를 미리 보여 주고, 사용자가 승인한 뒤에 파일을 씁니다. 원본 노션 페이지와 아티팩트는 수정하거나 지우지 않습니다.

### 노션

| 노션 데이터 | 이전 대상 |
| --- | --- |
| 학기 및 GPA | Semester. 인정학기는 `credited` 학기로, 학기 기간은 그대로 옮긴다 |
| 강의 목록 | Course. 강의 코드, 일련번호, 세부 분류, 교수, 학점, 평가 방식, 성적, 절평 점수, 수강 학기 |
| 강의 목록의 중간고사, 기말고사 | Exam |
| 강의 목록의 강의계획서 | 과목 폴더의 Syllabus에 내려받고 Material로 등록한다. 같은 파일이 이미 있으면 내용 해시로 확인해 건너뛴다 |
| 강의 코드, 강의 분류, 평어, 교수 정보 | `catalog.json` |
| 과목 페이지의 강의 정리 | Session과 Note. `2주차-1`은 러프 노트로, `2주차-1 정리`는 같은 회차의 복습 노트로 옮긴다. 태그(러프, 복습)로 종류를 판단한다 |
| 과목 페이지의 강의 점수 분포 | GradeComponent와 ScoreEntry. 하위 항목이 있는 항목은 하위 점수로 옮긴다 |
| 과목 페이지 본문의 규칙 | GradePolicy. Claude가 글을 읽어 출결 상한, 최저점 제외, 지각 규칙을 구조화한 후보를 만들고, 사용자가 확인한다. 원문은 `notes`에 남긴다 |
| 과목 페이지 본문의 나머지 글 | 과목 메모. 시험 경향, 시험 장소 같은 내용 |

- 노션 페이지 본문은 Notion MCP로 읽어 마크다운으로 변환한다. 노션 전용 블록(토글, 열, 콜아웃)은 Folio의 대응 문법으로 바꾸고, 이미지는 내려받아 노트의 assets에 둔다.
- 과목과 iCloud 폴더는 학기와 과목 코드로 짝짓는다. 예를 들어 노션의 "2026 가을학기, EC 4207-01, 그래프 이론"은 `2026-3/EC4207 그래프 이론`과 짝이다. 짝을 찾지 못한 과목은 목록으로 보여 주고 사용자가 고른다.
- 폴더가 없는 과목(인정학기 과목, 콜로퀀움 등)은 폴더를 만들지 않고 `transcript.json`에 성적 기록만 남긴다. 나중에 폴더가 생기면 일반 과목으로 전환한다.
- 이전이 끝나면 학기별 총 학점, 유효 학점, GPA를 노션 값과 나란히 보여 주고, 다른 곳이 있으면 원인을 표시한다.

### 아티팩트

- 중간고사 대비 아티팩트의 퀴즈 문항, 모범답, 풀이 기록, 판정, 손필기 오답 기록, 공부 시간 기록을 내보내 QuizCard, ProblemSet, Event로 옮긴다. 아티팩트의 데이터베이스에 저장된 기록은 아티팩트 데이터 도구로 읽는다.
- 이전된 풀이 기록은 복습 스케줄러의 초기 상태를 계산하는 데 쓴다. 틀린 카드가 많은 단원은 짧은 간격에서 시작한다.
- LR 오토마톤 스테퍼와 Petersen Graph는 해당 과목의 위젯으로 옮기고 단원에 연결한다.
- EC3204 오답 노트는 내용을 확인한 뒤 같은 방식으로 옮긴다.

### 노타빌리티

- 사용자가 노타빌리티에서 과목별로 PDF를 내보내 과목 폴더의 Archive에 둔다.
- 앱은 이 파일을 "이전 필기" 역할로 등록하고, Claude가 파일 이름과 내용으로 강의 회차나 단원을 제안한다.

### 옵시디언

옵시디언 볼트에서는 아무것도 옮기지 않습니다. 볼트는 지금처럼 분야별 개념 노트 저장소로 유지합니다. 이번 학기 과목의 `Lectures` 노트처럼 특정 과목에 묶인 노트는, 필요하면 과목 노트에서 `obsidian://` 링크로 참조합니다.

## 보류 사항과 미결정 사항

### 보류 사항

- 학교 LMS에서 과제와 공지를 자동으로 가져오는 기능. 데이터 구조는 미리 대비해 두었다.
- 필기의 수식 인식.
- Mac에서 iPad의 Claude 요청을 대신 처리하는 중계 모드.
- 명령줄 도구의 액션을 MCP로 여는 것. 셸이 없는 Claude 앱에서 Folio 데이터를 다뤄야 할 때, 클라이언트가 실행하는 표준 입출력 방식(`folio mcp`)으로 `folio actions --schema`와 같은 목록에서 만든다. 상시 서버는 두지 않는다.

### 구현 전 확인할 사항

- [x] Claude 구독 인증으로 개인 앱에서 Claude Code를 호출하는 것이 약관상 허용되는지. 사용자가 허용했다(2026-10-24). Mac은 구독을 기본으로 쓰고, 설정에서 API로 바꿀 수 있다
- [ ] GIST 학칙의 재수강 성적 처리, 졸업 평점 산정 방식, 우등 졸업 기준
- [x] 노션의 "유효 학점" 정의가 이 명세의 계산과 같은지. 수식은 MCP로 열 수 없어 값으로 확인했다(2026-10-22). 유효 학점은 같다. 노션의 "총 학점"은 W 과목의 학점도 더하므로, 가져올 때 W의 `countsInCredits`를 참으로 두었다. F와 U는 거짓이다
- [ ] 학기 폴더 번호 4를 겨울학기로 쓰는 것이 맞는지

- [ ] 기존 폴더 정리의 이동 계획 검토와 승인

### 새로 생기는 위험

- **유지보수 부담**: 공부 도구 전체가 직접 만든 앱 하나에 모인다. 시험 기간에 버그가 생기면 공부 흐름이 멈춘다. 모든 데이터를 일반 파일(마크다운, JSON, PDF)로 두는 것은 앱이 동작하지 않을 때도 내용을 읽을 수 있게 하기 위해서다.
- **동기화 충돌**: 기기별 로그로 대부분 막지만, 구조 데이터와 노트는 두 기기에서 동시에 고치면 충돌이 생길 수 있다.
- **옵시디언과의 이원화**: 개념 노트는 볼트에, 과목 노트는 Folio에 둘 수 있어서 같은 내용을 두 곳에 쓰게 될 수 있다. 과목 노트는 수업과 시험 중심으로, 개념 노트는 분야의 지식 중심으로 쓰는 구분을 유지해야 한다.
- **API 비용**: iPad에서 Claude를 쓰거나 구독 호출이 허용되지 않으면 API 사용료가 든다. 채점과 이미지 입력이 많을수록 비용이 커진다.
