# 입력 기기

Folio는 포인터(Mac, 트랙패드나 마우스를 붙인 iPad)와 터치(iPad, iPhone)로 쓴다. iPad는 둘을 오가므로 한 화면이 두 입력을 함께 받는다. 화면 요소마다 두 입력에서 어떻게 쓰는지 정하고 만든다. 포인터에서 편한 숨은 동작(칸 경계 두 번 누르기)은 손가락으로는 찾을 수도, 정확히 누를 수도 없다.

- **찾을 수 있는 길.** 포인터로 할 수 있는 일은 모두 터치에서도 보이는 길로 할 수 있어야 한다. 숨은 동작과 정밀한 동작(가는 표적의 두 번 클릭, ⇧-클릭, ⌥-끌기, 오른쪽 클릭, 마우스 올림)은 지름길로만 두고, 그것으로만 되는 일을 만들지 않는다. 같은 일을 메뉴 항목이나 보이는 버튼으로도 둔다.
- **바꿔 쓰는 짝.**

  | 포인터 | 터치 |
  | --- | --- |
  | 마우스를 올리면 보이는 정보와 버튼 | 늘 보이거나, 누르거나 끄는 동안 보인다 |
  | 오른쪽 클릭 메뉴 | 길게 누르기 메뉴. `.contextMenu` 하나가 둘을 준다. AppKit에서 직접 단 메뉴(`willOpenMenu`)는 iPad 쪽(`UIContextMenuConfiguration`)도 단다 |
  | 두 번 클릭 | 메뉴 항목이나 보이는 버튼. 두 번 누르기는 남겨도 되지만 유일한 길이 아니다 |
  | ⇧-클릭으로 범위, ⌘-클릭으로 하나씩 더하기 | 길게 눌러 시작한 뒤 누르기, 또는 고르기 모드를 켜는 버튼. 여러 줄을 고르는 목록은 `picks(picking:touch:hold:)` 하나로 받는다. 고르는 중인지는 칠한 행이 보이므로 쓰는 법 안내는 두지 않고, 끝내는 길이 따로 필요할 때만 짧은 상태와 버튼을 둔다 |
  | ⌥-끌기처럼 수식 키를 누른 끌기 | 보이는 다른 길(숫자 입력, 켜고 끄는 버튼) |
  | ⌘-클릭으로 링크 열기 | 누르면 열거나, 길게 누르기 메뉴의 "열기" |
  | 도움말(`.help`) | 터치에는 뜨지 않는다. 뜻(✦를 붙인 이유, 점이 알리는 상태, 줄여 쓴 이름)은 보이는 글이나 누르면 뜨는 팝오버로도 둔다. 쓰는 법 안내는 도움말로 충분하다 |
  | 키보드로만 하는 일(↑↓, 숫자 키, ⌘A) | 같은 일을 하는 버튼이나 메뉴. 하드웨어 키보드가 없는 iPad에서도 끝까지 쓸 수 있어야 한다 |

- **누르는 표적.** 터치의 표적은 보이는 모양이 가늘어도 44pt 이상이다. 칸 경계, 손잡이, 막대의 구역과 경계, 패널 가장자리처럼 가는 것은 `contentShape`로 누르는 자리만 넓히고 그림은 그대로 둔다. 이웃한 표적과 겹치면 가까운 쪽이 받는다. 포인터의 표적은 더 작아도 된다. 예외는 iPad와 iPhone의 크롬으로, Mac 비율을 지키려고 정한 크기다([창 구조](window.md)의 iPad).
- **명령.** 명령은 메뉴 막대(`CommandMenu`, `CommandGroup`)에 둔다. Mac과 iPadOS 26 모두 메뉴 막대가 있고, iPad에서는 ⌘를 누르고 있으면 목록이 뜬다. 키는 단축키 등록표(#116)에서 온다. 메뉴 막대 명령과 화면 안의 버튼은 같은 동작을 부른다.
- **나누는 자리.** 한 뷰가 두 입력을 함께 받게 짓는 것이 먼저다(`.contextMenu`, 누르기와 끌기 제스처, 포인터에서만 뜨는 `.help`와 `.pointerStyle`). `#if os(macOS)`로 나누는 것은 AppKit과 UIKit의 구현이 다를 때와, 마우스를 올릴 때만 보이게 할 것을 Mac에서만 숨길 때다. iPad는 트랙패드를 붙이기도 하므로 그런 것을 늘 보인다. 나눌 때는 두 쪽을 함께 쓴다(AGENTS.md "PR 전 점검").
