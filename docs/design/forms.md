# 폼과 컨트롤

만들기·편집 시트(`SheetForm`)와 설정 페이지, 그리고 시스템 컨트롤 대신 쓰는 Folio의 컨트롤이다. 공통 원칙은 [DESIGN.md](../DESIGN.md)에 있다.

## 폼

시트와 설정은 같은 모양의 폼이다. 시스템 설정 앱처럼 이름은 왼쪽, 값은 오른쪽인 행을 카드에 담고, 입력 칸처럼 보이는 상자는 두지 않는다. 폼은 빈칸을 채우는 서류가 아니라 이미 값이 들어 있는 목록처럼 읽혀야 한다.

```text
시험 추가                                   ← columnTitle
시험                                        ← Block 소제목(회색)
╭──────────────────────────────────────╮
│ 종류                      ( 중간고사 ⌃⌄ ) │ ← FormRow + Select
│ ──────────────────────────────────── │   (구분선은 글자 시작점부터)
│ 이름                           Midterm │ ← InlineField: 바탕 없음, 오른쪽 정렬
╰──────────────────────────────────────╯
일시와 장소
╭──────────────────────────────────────╮
│ 일시                             정하기 │ ← 비어 있는 선택 값: ghost 버튼
│ 장소                        (  예: C104 ) │ ← 짧은 값: pill
╰──────────────────────────────────────╯
메모                                        ← TextArea는 섹션 하나를 차지
╭──────────────────────────────────────╮
╰──────────────────────────────────────╯
  파일을 넣으면 시험 폴더 Exams/Midterm에 둡니다 ← note: 확인을 누르면 일어날 일
[지우기]                        취소  [추가] ← 지우기는 왼쪽, 주 동작 하나만 채움
```

- **골격.** 제목, `Block`과 `Card`의 묶음, 긴 글, 안내 한 줄, 버튼 줄 순서다. 항목이 여섯 개를 넘으면 뜻으로 묶어 `Block` 여러 개로 나눈다. 묶음 하나에 행 하나만 남는 분할은 하지 않는다.
- **시트의 높이.** `SheetForm`은 창의 콘텐츠 영역(`sheetRoom`)을 넘지 않고, 넘치면 제목과 버튼은 두고 폼만 넘긴다. 행이 바꾸는 즉시 쓰는 시트(자료 연결)는 `cancellable: false`로 "완료" 하나만 둔다.
- **행.** `FormRow`의 이름에는 콜론과 필수 표시(`*`)를 붙이지 않는다. 값과 컨트롤은 오른쪽 끝에 붙고, 둘 이상이면 나란히 둔다(날짜 칩, `–`, 시각 칩, ✕). 이름 아래 `detail`은 컨트롤만으로 알 수 없는 것(경로, 실제 시각과 날짜, 모델 크기)과 오류에만 단다. 값이 무엇을 하는지 되풀이하는 설명은 달지 않는다. 고칠 문제(없는 API 키)는 `warns`로 경고 색을 준다.
- **기기별 값.** 다른 기기와 나누지 않는 값에는 이름 옆에 "이 기기" 꼬리표를 붙인다(`FormRow(device:)`). 기기별 값만 따로 모으지 않는다. 같은 일(받아쓰기와 녹음, 연결 방식과 API 키)이 갈라진다.
- **접어 두는 값.** 드물게 바꾸는 값은 `DisclosureRow`("세부") 아래에 둔다. 카드의 마지막 행이면 `Card(clipped: true)`로 펼친 바탕이 모서리를 넘지 않게 한다.
- **검증.** 확인할 수 없는 상태면 확인 버튼을 끄고 이유를 그 행의 `detail`이나 시트의 `note`에 한 줄로 쓴다(액션의 `refusal`). 꺼진 버튼만으로는 왜 저장이 안 되는지 알 수 없다. 경고창을 띄우거나 칸을 빨갛게 칠하지 않는다.
- **안내 한 줄.** 확인을 누르면 파일이나 폴더가 생기는 것처럼 눈에 보이지 않는 일이 일어나면 `note`로 미리 말한다("폴더 2026-2를 만듭니다").
- **버튼.** 확인 버튼 이름은 하는 일의 동사(추가, 저장, 넣기)이고 "확인", "완료"로 쓰지 않는다. return이 확인, esc가 취소다. 지우기는 왼쪽 끝에 떨어뜨려 두고 한 번 더 묻는다.
- **설정은 시트가 아니다.** 늘 열려 있는 폼(설정, 과목 정보)은 `Page` 안에서 같은 `Block`·`Card`·`FormRow`로 그리고 바꾸는 즉시 저장한다. 확인 버튼이 있는 폼은 새로 만들거나 여러 칸을 한 번에 고치는 시트와, API 키처럼 다 입력한 뒤에야 쓸 수 있는 값뿐이다.
- **설정의 행은 선언에서 그린다.** 켜고 끄기, 숫자, 고르기, 시각, 글 항목은 `SettingItem`의 선언으로 `SettingBlock`과 `SettingRow`가 그린다. 화면에 행을 손으로 더하지 않고 묶음(`SettingGroup`)에 항목을 놓는다. 다른 행을 켜고 끄는 토글은 그 행의 스위치가 되고, 꺼진 동안 행의 값은 흐리게 남는다. 목록을 고치거나 폴더를 고르는 항목만 그 탭이 따로 그린다.

## 값에 맞는 컨트롤

| 값 | 컨트롤 | 고르는 기준 |
| --- | --- | --- |
| 짧은 글(이름, 설명) | `InlineField` | 바탕도 테두리도 없이 오른쪽 정렬. 안내 글은 "예: …"로 실제 값의 예를 든다 |
| 짧은 값(숫자, 코드, 강의실) | `TextField` + `.pill(width:)` | 회색 캡슐, 오른쪽 정렬, 고정폭 숫자. 폭은 값의 길이에 맞춘다 |
| 범위가 있는 숫자 | `NumberField` | 좌우로 끌어 바꾸고 누르면 입력. 부호 있는 값의 크기만 보일 때는 `magnitude: true`이고 방향은 옆 낱말이 말한다(`[5] 분 전`) |
| 숫자 여럿 | `NumberTagsField` | 숫자 칩 목록과 더하기 |
| 렉처의 쪽 구간 | `PageRangeField` | [자료와 렉처](patterns-lectures.md)의 쪽 막대 |
| 렉처를 단원으로 나누기 | `SectionEditor` | [자료와 렉처](patterns-lectures.md)의 렉처 나누기 |
| 짧고 고정된 선택지 | `Select` | ⌃⌄가 붙은 회색 칩. 안은 시스템 `Menu`다 |
| 사용자 데이터로 늘어나는 목록 | `Combobox`, `MultiCombobox`, `CommandList` | 같은 칩이 검색 칸이 있는 팝오버를 연다. 여럿이면 "3개 · 첫 항목". 찾는 이름이 없을 때 만들어야 하면 `CommandList`의 `create`로 고르기와 만들기를 한 행에 둔다 |
| 2~4개의 상호 배타 보기 | `SegmentedControl` | 트랙 안의 판(`layout: .track`). 다섯 개가 넘으면 `layout: .flow`로 줄을 바꾼다. 가로로 넘기면 뒤쪽이 가려지므로 쓰지 않는다. 도구 줄과 유리 위에서는 `size: .small`. 기호만으로 뜻이 통하면 `systemImages`로 쓰고 글자는 도움말과 VoiceOver 이름으로 남긴다 |
| 낱말로는 결과가 그려지지 않는 2~4개 | `RadioCards` | 작은 그림과 이름 타일(수업 시작의 배치) |
| 여러 개를 각각 켜고 끄기 | `ToggleGroup` | 칩 줄. 한 글자 선택지(요일)는 `shape: .circle`. 하나는 늘 켜져 있어야 하면 `allowsEmptySelection: false` |
| 몇 개의 상태를 차례로 | `StepToggle` | 누를 때마다 다음 상태, 오른쪽 클릭으로 바로 고르기 |
| 켜고 끄기 | `Switch` | 시스템 스위치 |
| 날짜와 시각 | `DateChip`, `DatePanel`, `TimePicker` | 날짜는 달력 팝오버, 시각은 끌거나 시계 다이얼에서 시를 고른 뒤 분을 고른다. 글자로 입력받지 않아 틀린 값이 들어올 수 없다. 다른 칩의 팝오버에도 `DatePanel`을 쓴다 |
| 과제의 반복 | `RepeatMenuItems`, `RepeatRuleRows` | 과제 시트와 빠른 추가가 같은 것을 쓴다 |
| 성적 | `GradeSteps` | 성적 눈금 |
| 없어도 되는 값 | ghost 버튼 → 칩 | 비어 있으면 "정하기" 같은 동사 버튼, 정하면 칩과 지우기 ✕ |
| 여러 줄 글 | `TextArea` | 다른 카드 안에 넣지 않고 섹션 하나를 차지한다. 글을 따라 자라다 안에서 넘기고, 시트가 보여 주는 높이를 넘지 않는다. 끌어서 늘리는 손잡이는 터치에 없으므로 두지 않는다 |
| 거르기 | `SearchField`, `.toolbarField()` | 틀과 도구 줄 위에서는 `.toolbarField()` |

켜진 칩의 색은 하나다. 줄로 늘어선 칩(`ToggleGroup`, `SegmentedControl(layout: .flow)`)은 강조색 `tint` 바탕에 `ink` 굵은 글자이고, 트랙 안의 판(`layout: .track`)만 `card`다.

## 시스템 컨트롤 대신 쓰는 것

시스템 컨트롤은 저마다 테두리, 높이, 회색이 달라 한 행에 놓으면 리듬이 깨지고 종이색 위에서 차갑게 뜬다. 그래서 보이는 컨트롤은 Folio의 것으로 바꾸고 그 안의 동작은 시스템 것을 쓴다(원칙 8, `design-control`).

| 시스템 | Folio | 바꾼 이유 |
| --- | --- | --- |
| `Picker`(메뉴), 팝업 버튼 | `Select` | 테두리 있는 버튼이 행 안에서 두껍다 |
| `Picker(.segmented)` | `SegmentedControl` | 회색과 높이가 종이에 맞지 않고 유리 위에서 바꿀 수 없다 |
| `DatePicker` | `DateChip`, `MonthCalendar`, `TimePicker` | 고른 날을 과목 색으로 보이고, 달력이 늘 6줄이라 크기가 변하지 않는다. 시스템 시각 선택기는 플랫폼마다 모양이 다르고 5분 단위로 막을 수 없다 |
| `Stepper` | `NumberField` | 작은 화살표 대신 값 자체를 끈다. 보조 기술에는 `Slider`로 보인다 |
| `TextField(.roundedBorder)` | `InlineField`, `.pill()` | 상자 없는 값이나 캡슐 |
| `Form(.grouped)` | `Card` + `FormRow` | 종이 위 흰 카드. 시스템 `List`·`Form`을 꼭 써야 하면 `paperList()`로 바탕만 맞춘다 |
| `Button(.bordered)` | `.ghost`, `.ghostIcon` | 글자 버튼이고 호버 때만 캡슐이 비친다 |
| 툴바의 시스템 버튼 | `.toolbar` | 캡슐이 낮은 툴바 줄을 채운다 |
| `.searchable` | `SearchField`, `.toolbarField()`, ⌘K 팔레트 | 검색 칸의 위치와 모양을 창 구조에 맞춘다 |
| `Label`의 아이콘 간격 | `GhostLabelStyle` | 시스템 간격이 버튼 사이 간격보다 넓어 아이콘이 앞 버튼에 붙어 보인다 |
| 글꼴 크기로 키운 SF Symbol | `LineIcon` | 기호마다 폭이 달라 글자 시작점이 흔들린다 |
| `.inspector` | FAB와 떠 있는 패널 | 본문을 좁히고, Mac에서는 페이지를 툴바 밑으로 끌어올린다 |
| 스크롤 막대 | `overflowFade(_:)` | [패턴](patterns.md)의 "넘기는 영역" |
| 페이지의 스크롤 바운스 | `Page`가 끈다 | 끝을 넘어 늘어난 페이지가 오늘 화면의 노을을 패널 가장자리에서 떼어 낸다. `scrollBounceBehavior`는 내용이 짧을 때만 끌 수 있어 플랫폼 스크롤 뷰의 바운스를 직접 끈다 |

메뉴 단추는 `.menuButton(tinted:indicator:)`다. `.button` 메뉴에 Folio의 button style을 주면 pop-up으로 돌아가므로, 시스템 plain이나 borderless에 손가락 포인터를 더한다. 시스템 스타일을 꼭 감싸야 하는 자리(Link, 행 전체)는 `.pointing(.plain)`이나 `.pointing(.bordered)`다.

시스템 것을 그대로 쓰는 것도 있다. `sheet`, `popover`, `Menu`와 `contextMenu`의 내용(그 안의 `Toggle`과 `Picker`는 체크 항목이 된다), `confirmationDialog`, `Toggle(.switch)`(`Switch`가 감싼다), `TextEditor`, `ColorPicker`, `ContentUnavailableView`다. 창 관리, 키보드, 접근성처럼 다시 만들면 손해인 동작이 들어 있거나 이미 종이 위에서 어색하지 않은 것들이다.
